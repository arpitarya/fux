# Handoff: the `.fux` directory defined + URL source moves in

**One-liner:** `.fux/` becomes a declared, self-describing directory —
committed planes (`index/`, `sources/`, `middleware/`) vs derived planes
(`runtime/`, `cache/`) — and the URL source built under ADR-0010 moves
fully inside it: URL list to `.fux/sources/urls` (one per line), the CDP
middleware to `.fux/middleware/cdp.py`, its tunables to `fux.toml`.

**Owner / executor:** Claude Code — **Sonnet**. *Why Sonnet:* every design
decision below is closed and referenced; what remains is well-specified
implementation against a written DoD with tests that can catch a bad one.
The one judgment-heavy piece (the layout itself) was decided in this
session (Cowork/Opus-class) and is frozen in §5 — the executor implements
it, never redesigns it.

**Status:** Ready to build.

**Stress-tested:** devils-advocate pass, 2026-08-10 (Cowork). Challenged:
*(1) consumer-edited code inside a dotdir* — "dotdirs read as tool-owned;
users won't look there." Survived on precedent: `.github/workflows/` and
Husky's committed [`.husky/`](https://github.com/typicode/husky) are
exactly consumer-edited code in committed dotdirs; mitigation carried into
the spec: the file's own header + `.fux/README.md` must say "yours,
committed, edit freely." Residual risk: linters that skip hidden dirs by
default (ruff does) won't lint the middleware — accepted, it's consumer
code, not a CI target; note it in the README. *(2) CDP tunables in
`fux.toml` couple core to one middleware's vocabulary* — real risk to the
adapter cap's spirit; **blocked the naive design** (typed `cdp_port` keys
in `config.py`) and forced the opaque-table contract in §5.3: fux passes
`[sources.url.config]` verbatim, validates nothing inside it — the
[PEP 518 `[tool.*]` table pattern](https://peps.python.org/pep-0518/#tool-table).
*(3) riskiest assumption:* committed + derived under one dotdir with a
`.fux/.gitignore` could silently ignore a committed plane. Mitigations
specced: the ignore file lists ONLY derived dir names (never `*`), derived
dirs carry [`CACHEDIR.TAG`](https://bford.info/cachedir/), and `fux doctor`
gains a `git check-ignore` assertion on `index/`. No pre-mortem: not a
release, every step reversible.

## 1 · Context & background

- ADR-0010 (⏳ proposed, unratified — amendable in place) landed the URL
  source 2026-08-10: `[sources.url]` with an **inline `urls = [...]`
  list**, `cdp_middleware.py` at **repo root** with tunables as **module
  constants**. All three placements are what this handoff relocates.
- Arpit's direction (2026-08-10, in session): the URL list can be huge —
  it belongs in a separate file under `.fux/`; the middleware belongs
  under `.fux/` too; its config belongs in `fux.toml`; and `.fux/` itself
  needs a systematic definition.
- `.fux/` today holds only `index/` (committed). M2 will add derived
  runtime segments, M4 a fetch cache — the committed/derived split is
  arriving regardless; defining it now is cheaper than retrofitting.

## 5 · Technical approach (decided — do not re-litigate)

### 5.1 The layout (→ ADR-0011)

```
.fux/
  README.md      committed · written-if-missing by fux · describes THIS table
  .gitignore     committed · written-if-missing · lists ONLY derived dirs, never *
  index/         committed · the wire-format index (ADR-0004)
  sources/       committed · large line-oriented source lists (urls; M4 may add more)
  middleware/    committed · consumer-owned code (cdp.py) — edit freely
  runtime/       derived  · reserved for M2 accelerator segments · CACHEDIR.TAG
  cache/         derived  · reserved for M4 ARC fetch cache      · CACHEDIR.TAG
```

**The rule that makes it systematic:** every child of `.fux/` is declared
here as *committed* or *derived*; derived dirs are self-tagged
([CACHEDIR.TAG spec](https://bford.info/cachedir/), the pytest/mypy
pattern — pytest writes `.gitignore` + `CACHEDIR.TAG` + `README.md` into
its own cache dir:
[cacheprovider](https://docs.pytest.org/en/latest/_modules/_pytest/cacheprovider.html),
[mypy #8193](https://github.com/python/mypy/pull/8193)); anything
undeclared is a doctor warning. M2/M4 may rename their reserved dirs in
their own ADRs — they update the table, the README template, and the
ignore list in the same change.

### 5.2 The urls file

`.fux/sources/urls` — one URL per line, the shape git diffs and merges
(the same argument that sharded the index; a 5k-entry inline TOML array is
one diff hunk and one merge conflict). Parse rules in §2. Deterministic
order: loader dedupes + sorts before fetching, file order is presentation.

### 5.3 The config table

```toml
[sources.url]
middleware = ".fux/middleware/cdp.py"   # default; consumer may point elsewhere
urls_file  = ".fux/sources/urls"        # default
meta       = "hashed"                    # unchanged from ADR-0010

[sources.url.config]                     # OPAQUE — fux never reads keys
cdp_port   = 9222
settle_ms  = 500
load_timeout_s = 30
launch_chrome  = true
```

Contract grows one optional hook: `configure(config: dict) -> None`,
called once after import with the table (or `{}`). `fetch`/`connect`/
`close` unchanged. Fux treats the table as opaque bytes-to-the-middleware
— the PEP 518 tool-table discipline keeps the adapter cap intact: core
knows there *is* config, never what it *means*.

### 5.4 Sequencing

1. `fuxdir` layout module + tests → 2. config changes (`urls_file`,
`config` table, new defaults, inline-`urls` rejection) + tests →
3. `urlsrc.read_urls` + `configure` call + tests → 4. `git mv` the
middleware, rewrite its header ("yours, committed"), constants → defaults
overridden by `configure` → 5. doctor checks → 6. docs (§9.5) → 7. full
verify.

## 6 · Non-negotiables / constraints

- **$0, stdlib-only** — no new deps anywhere, including tests.
- **`src/fux/` keeps zero network code**; sockets exist only inside the
  consumer's middleware file. Never import the middleware except under
  `--refresh-urls`.
- **Byte-determinism** — same sources + same urls file + same fetched
  text → identical shards. No wall-clock, no set-order dependence
  (sort urls, sort dict keys as the canonical writer already enforces).
- **Never overwrite consumer files**: `README.md`/`.gitignore` in `.fux/`
  and the middleware are write-if-missing only.
- **`.fux/.gitignore` must never contain `*` or ignore a committed
  plane** — list derived dir names explicitly.
- **Offline law unchanged**: plain ingest carries `url:` records forward
  byte-identically; only `--refresh-urls` touches the middleware.
- **Do not touch:** `archive/**` (reference-only), `tools/pruning-eval/**`
  (frozen), `store/canonical.py` semantics, shard count, ADR-0004's frozen
  fields. Do not renumber ADRs (0005–0009 stay reserved).
- Docs style: short points, no walls of text (CLAUDE.md documentation
  style is binding).

None external. No secrets. Chrome is NOT needed — all tests stay offline

## 8 · Edge cases & risks

- `.fux/sources/urls` missing but `[sources.url]` configured →
  `FuxError` naming the path, only when `--refresh-urls` runs (offline
  ingest must not care).
- Duplicate URLs in the file → deduped silently (sorted-set semantics,
  matching overlapping-dirs behavior in `gitdir.walk_sources`).
- `configure` raising → `FuxError` at once (misconfiguration, not a
  per-URL skip).
- A consumer-edited `.fux/.gitignore` that DOES ignore `index/` →
  doctor error (the check exists precisely for this).
- `git mv` on a file modified in the same change → mv first, edit after,
  one commit; history stays.
- Windows: CACHEDIR.TAG + `.gitignore` writes are plain-ASCII bytes; use
  `\n` explicitly (the v0.30.0 release-day Unicode-console lesson,
  WORKLOG 2026-08-11).
