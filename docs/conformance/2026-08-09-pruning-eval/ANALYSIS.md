## What was measured

One scorer (archived v0.26 BM25F), three arms, varying **only** the index:

| arm | postings | `df` / `n` / `avg_wlen` |
|---|---|---|
| `baseline` | full | full |
| `pruned` | KL top-*k* per document | **recomputed from the pruned postings** |
| `diag` | KL top-*k* per document | borrowed from the full index (attribution only) |

Recomputing statistics is the correctness point: production's `D/` holds `df`
over the *pruned* index. Borrowing baseline statistics would make scores line up
and would measure a system nobody is going to ship.

|---|---|

## Diagnosis

### 1. The gate passed on a treatment that did not happen

Top-*k* prunes a **document's vocabulary**. These corpora barely have one:

| corpus | distinct terms per document — median / p90 / p99 / max |
|---|---|
| acme | 32 / 81 / 156 / 407 |
| orbit | 36 / 89 / 150 / 432 |
| synth | 46 / 62 / 67 / **72** |

The paper's §5 size model assumes ~10⁴-word documents — ~2 000 distinct terms,
128 kept: **≈ 6 % retention**. Measured retention was **97.9 % / 98.4 % /
100 %**. On synth the "pruned" index is *byte-identical* to the baseline index.

**k=128 on a 32-term document and k=128 on a 2 000-term document are different
treatments.** The experiment measured the first and the threshold was written
for the second.

### 2. Where pruning did bite, it hurt

k=64 still retains 62–97 % of terms among the documents it touched — an order of
magnitude milder than production — and acme lost **9.5 points** on exactly those
documents. That is the only real signal in the run, and it points against P1.

### 3. The KL criterion drops topical terms on a homogeneous corpus

acme's k=64 failure catalogue (5 lost top-5 hits: 4 `term-pruned`, 1
`score-compressed`; 3 missing-postings, 2 shifted-statistics) shows the
criterion pruning **`webhook` out of `docs/api/webhooks.md`** and **`payments`
out of a payments document** — terms frequent in the document *and* frequent in
the collection, so their KL ratio is modest. One query fell from rank 5 to 88.

An enterprise mega-project corpus — the stated design point — is **more**
topically homogeneous than acme, not less. This failure mode should be expected
to worsen at the target scale, not wash out.

### 4. Rare-term loss is not the problem here

The rare-term slice moved 0.00 / 0.00 / −5.26 pts. **Do not build the
Bloom-signature mitigation (M8) on this evidence** — it addresses a failure mode
this run did not find, while the failure mode it *did* find (frequent-topical
terms pruned from their own document) has no mitigation designed.

## Unresolved

- **Whether P1 is true.** This run does not answer it in either direction. The
  k=64 result is suggestive of a problem but is an extrapolation across a
  10× difference in treatment strength.
- **Whether a KL criterion is the right selector at all** for topically
  homogeneous corpora, or whether the frequent-topical-term loss needs a
  different objective (e.g. a per-document floor on the highest-`tf` terms).
  Out of scope for M1; worth a compare doc if change 3 reproduces the pattern.
- **Whether the three corpora should weigh equally** — the handoff's open
  question. Moot this run (all three returned 0.00), live again for change 3.
