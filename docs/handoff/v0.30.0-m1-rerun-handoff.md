# Handoff: v0.30.0 M1-rerun — make P1 decidable

**One-liner:** Re-run the pruning gate so it actually tests the treatment —
long documents, retention-matched arms, candidate-recall as the metric —
and decide whether the committed index can be small.

**Owner / executor:** Claude Code — **Opus** throughout (see §11)
**Status:** Ready to build
**Stress-tested:** [ADR-0017](../adr/0017-pruning-eval-gate.md) is itself
the debate that produced this handoff — it refused a letter-of-the-rule
PASS and named exactly why the experiment was void. Packaging added three
challenges. *(1)* "Just re-run on bigger documents" would have repeated the
same design with a better corpus and still measured the wrong metric — the
index is a candidate generator feeding a re-score stage, so hit@5 of the
index was never the system's metric. Fixed: recall@20 is the gate. *(2)*
The failure catalogue shows the *criterion* is defective for homogeneous
corpora, independent of corpus size — so re-running arm 1 alone would have
burned a corpus to re-learn a known defect. Fixed: five arms.
*(3)* Testing several criteria at a fixed *k* would compare different
retentions and repeat ADR-0017's error one level up. Fixed: retention is
matched across arms and is the registered axis.
**Residual risk:** the long-document corpus is new and unvalidated; a bad
corpus can void this run the way small documents voided the last one. §5.1
makes corpus validation a gate *before* the arms run.

## 1. Context & background

[ADR-0017](../adr/0017-pruning-eval-gate.md) measured P1 and returned
**INCONCLUSIVE**: at k=128 the delta was exactly 0.00 points because
pruning touched 0–2.5 % of documents — the eval corpora have 32–46 distinct
terms per document, so "keep the top 128" removed nothing. Production
documents carry ~1 000–2 000 distinct terms, where the same rule discards
~94 %. The treatment has never been tested.

The run did produce one real signal, and it points at the criterion rather
than at pruning: at k=64, KL selection dropped `webhook` from
`docs/api/webhooks.md` and `payments` from a payments document — because KL
divergence rewards terms that are *rare across the collection*, and a
corporate corpus is topically homogeneous by nature. That is a structural
mismatch with Fux's design point.

[`compare/pruning-criterion.compare.md`](../compare/pruning-criterion.compare.md)
holds the resulting design: a combined selector under an adaptive retention
budget, gated on candidate recall. This handoff measures it.

## 2. Definition of done

**Phase 1 — the corpus (gate before anything else)**
- [ ] A long-document corpus exists under lab control, deterministic and
      re-fetchable, with a manifest pinning exact document identities.
- [ ] Its distribution is *reported and validated*: median/p90/p99 distinct
      terms per document, with **median ≥ 500 distinct terms**. Below that
      threshold, STOP — the corpus cannot exercise 6 % retention and the run
      would be void (this is ADR-0017's lesson, promoted to a gate).
- [ ] An eval set exists for it — query/gold-document pairs — with the
      construction method documented and its weaknesses named honestly.
- [ ] The two existing realistic corpora (acme, orbit) are retained as
      *secondary* corpora, reported but not gating (they are too short to
      gate on, per ADR-0017).

**Phase 2 — the selector**
- [ ] Rules A, B and C implemented per
      [`pruning-criterion.compare.md` §7](../compare/pruning-criterion.compare.md),
      as pure stdlib functions with unit tests, portable into
      `src/fux/ingest/` unchanged.
- [ ] The adaptive budget (`max(floor, share × vocab)`) replaces fixed k
      everywhere in the harness.

**Phase 3 — pre-registration (frozen before the first gating number)**
- [ ] `tools/pruning-eval/PRE-REGISTRATION-v2.md` committed, stating: the
      five arms, the retention rungs (6 %, 15 %, 30 %), **recall@20 as the
      sole gate metric**, everything else as diagnostic, the PASS/FAIL rule
      in §5.4, and the prediction from the compare doc (arm 4 ≈ arm 5 at
      6 %; arm 1 the outlier).

**Phase 4 — the run**
- [ ] Five arms × three rungs × all corpora, with retention and prune
      coverage reported per cell.
- [ ] Failure catalogue for every arm that loses a gold document from the
      candidate set, with causes classified.
- [ ] Harness validity checks all pass (§9).

**Phase 5 — the verdict**
- [ ] `docs/adr/0018-pruning-criterion-rerun.md` records the numbers, the
      selector decision, and PASS / FAIL / INCONCLUSIVE against §5.4.
- [ ] Conformance filing under `docs/conformance/<date>-pruning-rerun/`.
- [ ] `pruning-criterion.compare.md` status → accepted (or amended);
      ADR-0017 gains a one-line forward pointer; OPEN-WORK P1 row updated.
- [ ] On PASS: W-01 (M0b scaffold) unblocks — but is **not** executed here.

## 5. Technical approach (decided)

### 5.1 The corpus — the part that decides whether this run is worth anything

Requirement: real prose, long documents, open vocabulary, deterministic and
re-obtainable, license-clean, no auth.

**Recommended: the RFC corpus.** ~9 500 documents of technical prose,
10³–10⁴ words each, plain text, stable URLs, public domain-ish and
redistributable by reference. It is close in register to the enterprise
documents Fux targets (specifications, procedures, cross-references) and it
is *topically homogeneous within clusters* — which is exactly the condition
that broke the KL criterion, so it tests the real weakness rather than
hiding it.

Fetching is a **lab activity**, not an engine activity — the offline law
constrains the engine, not the eval harness. Fetch once into the lab, pin a
manifest of `(id, sha256)`, and make every later run read from the local
copy. If network fetching is unavailable in the execution environment,
STOP and tell me rather than substituting a synthetic corpus quietly.

**Second corpus, no fetching required:** the repo's own long-form docs plus
`archive/v0.26-docs/` — a few hundred documents, genuinely long (ADRs, the
paper, compare docs), genuinely homogeneous. Small, but it is *the actual
target domain*, so a disagreement between it and RFCs is itself a finding.

**Eval set construction.** For RFCs, derive queries from section headings
and abstract sentences with the source document as gold — document the
method and its bias (heading-derived queries favour heading terms, which
flatters Rule A; report that plainly and weight it in the verdict). If a
better construction is available, use it and say why. **A weak eval set
honestly described beats a strong one silently assumed.**

**The corpus gate:** report the distinct-terms distribution *before*
running arms. Median < 500 → stop.

### 5.2 The selector

Implement exactly [`pruning-criterion.compare.md` §7](../compare/pruning-criterion.compare.md).
The two points that are easy to get wrong and invalidate the run:

- **Rule C runs after every document's local pass, and statistics are
  computed after Rule C.** The sweep changes `df`. Order: local select →
  global sweep → recompute `df`, `n`, field-length sums over the final kept
  postings → build. Never borrow unpruned statistics into the pruned arm.
- **Selection uses the unpruned collection model** (it must — you cannot
  rank terms by impact against statistics that depend on the selection).
  That is a two-pass build, not an inconsistency; document it in the ADR so
  a later reader does not "fix" it.

### 5.3 The metric — the reframe

**Gate on recall@20**: does the gold document reach the candidate set that
would be fetched and re-scored? Rationale: Fux ranks in the index, fetches
top-k, then re-scores passages on fetched bytes — a document falling from
rank 1 to rank 8 costs nothing. Mackenzie et al. (SIGIR '24) measure this
directly: pruning's recall reductions produce "no significant differences"
in final results once a re-rank stage runs.

Report as **diagnostics only**: recall@50, hit@5, P@10, MRR, rare-term
slice, per-pruned-document slices, and the failure catalogue. These inform
the write-up; they do not gate.

### 5.4 Pre-registered rule — freeze before the first gating number

| outcome | condition (on the **gating** corpus, recall@20, 6 % retention) | action |
|---|---|---|
| **PASS** | best arm within **2 pts** of arm 5 (no pruning) | selector decided; W-01 unblocks |
| **PARTIAL** | best arm within 2 pts at 15 % or 30 % but not 6 % | re-budget the paper's §5 size model at that retention; W-01 unblocks with the amended number |
| **FAIL** | no arm within 2 pts of arm 5 at any rung | option E: index is 0.6–1.5 GB; partial clone + external-shards-only become mandatory; `storage-architecture.compare.md` takes a size amendment |
| **VOID** | corpus gate fails, or prune coverage < 50 % of documents at 6 % | the run is not evidence; say so, do not report a verdict |

**The threshold does not move after numbers exist.** If the result is
ambiguous, write it up as ambiguous — ADR-0017 is the precedent, and it was
the right call.

## 8. Edge cases & risks

- **The corpus fetch is unavailable or the corpus is unusable.** Stop and
  report; do not substitute synthetic data. A void run must announce itself.
- **Heading-derived queries flatter Rule A.** Known bias; report it and
  discount Rule A's apparent contribution accordingly in the ADR.
- **Rule C blows the retention budget.** The sweep adds postings after the
  local budget is spent. Report *actual* retention per arm; if arm 4's
  actual retention exceeds arm 2's materially, the comparison is unfair and
  δ must be tuned down until retentions match — matched retention is the
  whole point.
- **An arm wins on one corpus and loses on the other.** That is a finding,
  not a tie-break problem: RFCs and the repo's own docs differ in exactly
  the way that matters (register, homogeneity). Report both; let the
  homogeneous one carry more weight, since it is the design point.
- **Everything passes easily.** Suspect the corpus or the eval set before
  believing it — re-check prune coverage and the k=∞ no-op arm first.

## 9. Testing & validation

- Selector unit tests: Rule A picks heading terms; Rule B respects the
  budget; **Rule C is order-independent** (shuffle term iteration → same
  kept set); budget floor honoured on tiny documents; ties broken on doc id.
- Harness validity, all required to pass before any verdict:
  baseline reproduces the archived engine's recorded numbers; `k = ∞` /
  100 % retention is a byte-identical no-op; two runs produce identical
  `report.md` sha256; **retention actually achieved is within ±1 pt of the
  rung for every arm**.
- Reproduce command in the conformance filing must actually reproduce.

## 11. Execution notes (model)

**Opus throughout, unlike M1.** This is a measurement-design task, and the
last one failed at measurement design, not at coding: the corpus gate, the
retention matching, and the fairness of the arms are all judgment calls
that a cheaper model resolves optimistically. The verdict phase especially
— ADR-0017 exists because a model was willing to refuse a PASS that the
letter of the rule permitted, and that behaviour is what this handoff is
buying again.
