**Owner / executor:** Claude Code (see §11 for the model per phase)

## 1. Context & background

The v0.19–0.26 substrate engine was archived on 2026-08-09
(`archive/v0.26/`, docs at `docs/archive/v0.26-docs/`). The replacement
architecture — **index-and-refer** — is specified in
[`../paper/the-fux-index-paper.md`](../paper/the-fux-index-paper.md) and
[`../architecture-components.svg`](../architecture-components.svg), with
six verdict-first compare docs in [`../compare/`](../compare/README.md)
and the build sequence in [`../PLAN.md`](../PLAN.md).

The architecture's load-bearing assumption is **P1**: that keeping only
each document's top-k KL-ranked terms preserves ranking quality. Published
work (Carmel et al. SIGIR '01; Büttcher & Clarke CIKM '06) says bounded
early-precision loss is expected; nobody has measured it on Fux's corpora
with Fux's scorer. If P1 fails, the committed index cannot be small, and
the architecture returns to the snapshot designs — so **P1 runs before
anything is built on top of it.**

## 5. Technical approach (decided)

### 5.1 Sequencing — corrected by this handoff's debate gate

The plan said M0 (scaffold) → M1 (gate). **That is wrong and is hereby
amended:** scaffolding a package for an architecture that P1 may falsify is
exactly the "build the fun part first" failure the pre-mortem seat warned
about. Corrected order:

1. **M0a — hygiene.** Needed regardless of P1's outcome (the repo is
   already reset; its docs already lie).
2. **M0-ADR — naming.** Cheap, human-gated, unblocks vocabulary in every
   later doc.
3. **M1 — the experiment**, run as a *lab script against the archived
   engine*, in `tools/pruning-eval/` at repo root (new dir, deleted or
   promoted later). **No new package scaffold.**
4. **M0b — scaffold**, only on PASS.

If P1 fails, the repo is left in an honest state (accurate docs, a recorded
negative result, no orphan scaffold) and `storage-architecture.compare.md`
reopens per its trigger.

### 5.2 The KL selector

Document-centric pruning (Büttcher & Clarke): for document *d*, score each
term *t* by its contribution to the KL divergence between the document's
term distribution and the collection's:

```
score(t, d) = P(t|d) · log( P(t|d) / P(t|C) )
```

Keep the top *k* by score. Notes that are **binding**:

- `P(t|d)` from the document's own term frequencies; `P(t|C)` from the
  full collection frequencies (computed in a first pass over the *unpruned*
  corpus — the selector needs the collection model before it can prune).
- Deterministic tie-break on term (lexicographic) so the same corpus always
  yields the same kept set.
- The selector is a **pure function**: `(doc_tf: dict, collection_model,
  k: int) -> list[term]`. No I/O, no globals. It is written to be portable
  into `src/fux/ingest/` at M2 without change.
- Field structure (heading/path/body) is preserved for the kept terms —
  BM25F needs per-field tf; pruning selects *which terms survive*, not
  which fields.

### 5.3 The harness — the one thing that must be exactly right

**Vary only the index.** Both arms use the archived BM25F scorer, the same
parameters, the same queries, the same fusion settings. Arm A = the index
as v0.26 builds it. Arm B = the same pipeline with the pruning filter
applied at index-build time.

**Corpus statistics must be recomputed post-pruning.** This is the subtle
correctness point and getting it wrong invalidates the whole experiment:
in production, `D/` holds exact df **over the pruned index** — a term's df
is the number of documents in which it *survived* pruning, and `avg_wlen`
reflects pruned field lengths. The harness must recompute df, n, and the
field-length sums from the pruned postings, not reuse the baseline's. Do
not "fix" a score gap by borrowing unpruned statistics; that would measure
a system nobody is going to ship.

**Report, per corpus × per k:**
- hit@5, P@10, MRR (the metrics the archived eval harness already computes)
- a **rare-term slice**: metrics restricted to queries whose terms fall in
  the bottom df tercile of the collection — this is where pruning is
  theoretically expected to hurt, and it is the slice that tells us whether
  the Bloom mitigation (M8) is ever needed
- a **failure catalogue**: every query where the pruned arm lost a
  top-5 hit the baseline had, with the reason classified (term pruned from
  the winning doc / score compressed / tie reordering)

**Also report** the committed-size proxy: total kept postings at each k,
so P2's model gets an early empirical anchor for free.

### 5.4 Pre-registered threshold — do not move it

From the paper §8 and PLAN §M1, fixed **before** any number is seen:

| outcome | condition | action |
|---|---|---|
| **PASS** | mean hit@5 delta ≤ 2 pts at k=128 on **each** of the three corpora, and no single corpus worse than 3 pts | proceed to M0b, then M2 |
| **PASS-with-k=64** | k=64 also meets the above | record; top-64 becomes the default candidate (PLAN M8 item resolves) |
| **FAIL** | any corpus worse than 3 pts at k=128 | **stop the plan.** ADR-0002 records the kill, `storage-architecture.compare.md` reopens |

If the result lands ambiguously (e.g. 2–3 pts on one corpus), that is a
**human decision** — write it up, do not adjudicate it. Moving the
threshold after seeing numbers is forbidden and is the single worst
failure mode available in this task.

## 6. Non-negotiables / constraints

- **Stdlib only** for anything that could become production code (the KL
  selector, above all). The *harness* may use archived-engine imports and
  may use `statistics`/`json`/`csv` from stdlib; it may **not** introduce
  numpy/pandas/scipy, even for convenience — the selector must be portable
  as-is, and the repo's zero-dependency claim is the product.
- **Determinism.** No wall-clock values, no `random` without a fixed seed,
  no set-iteration-order dependence in anything that produces output.
  Re-running the harness on the same corpus must produce byte-identical
  reports.
- **Do not modify `archive/v0.26/`.** Read it, import it, run it. If the
  pruning filter needs a hook the archived code doesn't expose, add the
  hook **in the harness** (subclass/wrap/monkeypatch inside the lab
  script), not in the archived source. If that proves impossible, STOP and
  ask — do not edit the archive.
- **Do not touch** `docs/archive/`, `docs/paper/` (M7 owns the numbers),
  or any compare doc's verdict block except `ingest-mode-naming`'s, and
  that one only to record Arpit's ratified decision.
- **Agent-steering files are proposed, never auto-applied.** The CLAUDE.md

## 8. Edge cases & risks

- **The archived engine won't run.** Most likely blocker (moved paths,
  stale venv). Fix by invocation, escalate if not. Do not port the engine.
- **100k is too slow to iterate on.** Develop the harness against the small
  fixture corpus and acme/orbit first; run the 100k arm once, last.
- **Pruning changes df enough to shift scores globally**, making the
  comparison look worse than the user-visible reality. This is expected and
  is *the real system* — report it, don't correct for it. But do also
  report a diagnostic arm (pruned postings + baseline df) so the failure
  catalogue can attribute losses to the right cause.
- **A corpus has no rare-term queries**, making the slice empty. Report
  "slice empty" honestly — an empty slice is a finding about the eval set
  (the fixture corpus had exactly this problem with links, per archived
  ADR-0009), not a pass.
- **k=128 exceeds a short document's vocabulary.** Then pruning is a no-op
  for that document — correct behavior; make sure the harness reports what
  fraction of documents were actually pruned, or a "PASS" could be
  measuring nothing.
- **Tempting scope creep:** implementing block-max, or "quickly" trying
  BIC. Both are M3/M4. Refuse.

## 9. Testing & validation

- **Unit tests for the KL selector** (these travel with it to M2): known
  small distributions → expected ranking; tie-break determinism; k larger
  than vocabulary; empty document; a term appearing in every document
  scores ~0 (no discriminative power); collection model built from the
  unpruned corpus.
- **Harness self-checks:** identical-arm sanity (run Arm A twice → byte-
  identical report); no-op-pruning sanity (k = ∞ → metrics equal baseline
  exactly, which validates that the only difference is pruning).
- **Reproducibility:** the conformance filing includes the exact command;
  running it twice produces identical numbers.
- Commands: `cd archive/v0.26 && uv run pytest -q` (baseline engine health)
  · `uv run python tools/pruning-eval/run.py --help` (the harness)
  · the harness's own test file under `tools/pruning-eval/tests/`.
- **Manual check:** read the failure catalogue. If the losses are
  concentrated in one query type, say so in ADR-0002 — that pattern is
  worth more than the aggregate number.

## 11. Execution notes (models, per repo law)

The repo law says name the model on every handoff, with why:

- **M0a + M0-ADR + M0b — Sonnet.** Mechanical doc work and scaffolding
  against a fully specified target; cheap, fast, low judgment content.
- **M1 harness + selector — Sonnet**, with one exception below. The code is
  small and the spec above is tight.
- **M1 analysis and ADR-0002 — Opus.** Reading a failure catalogue,
  attributing losses to causes, and writing a kill-or-ship verdict against
  a pre-registered threshold is exactly the judgment work where the
  cheaper model quietly rationalizes a marginal result. Hand the raw
  outputs to a fresh Opus session for the verdict if the numbers land
  anywhere near the boundary.
