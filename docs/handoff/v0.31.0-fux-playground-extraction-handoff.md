# Handoff — v0.31.0: fux-playground

**Model: Opus.** The deliverable *is* the corpus and the golden set, and no
test can catch a bad one — a corpus with weak hazards or goldens that encode
today's ranking rather than the right answer will pass every check and be
worthless as a regression net. It also touches three non-negotiables
(offline-by-default, byte-determinism, hashed-meta-by-default). Per
[`CLAUDE.md`](../../CLAUDE.md) §"How work happens here", that is Opus work.
It was not close.

---

## 1. Why

`examples/playground/` is a 20-doc fixture living inside the engine repo. That
is wrong on three counts:

- **It pollutes the engine's own corpus.** `fux.toml` ingests `docs`,
  `README.md`, `CLAUDE.md` — but the fixture's docs sit in the same tree,
  inviting exactly the accident where the demo corpus and the dogfood corpus
  contaminate each other's measurements.
- **A fixture that ships inside the package is not a fixture.** The sdist
  excludes it by accident of layout, not by decision.
- **It cannot be graded.** It has no expected answers, so a ranking regression
  changes what it prints and nobody notices.

Replace it with a **sibling repo**: `~/my_programs/fux-playground`, a real
consumer of fux that happens to be graded.

**Arpit's framing, verbatim: "I do not want examples."** The `examples/`
directory goes away entirely. It is not moved, not kept as a stub.

## 4. The corpus

### 4.1 Domain

**Calder Group** — a fictional 10 000-engineer company. **Helix** — its
internal developer platform (service catalog, monorepo build graph, deployment
gates, golden paths). Nothing in the corpus references trading, markets, or
Anton.

This choice is deliberate and follows `CLAUDE.md` §"Litmus for any new work":
the design point is a very large corporation's mega-project, so the fixture
should look like one — multi-team ownership, an SSO'd internal wiki, a
deprecation with a migration deadline, standards that supersede each other.

Docs are **mixed types at realistic lengths (100–400 lines)** — frontmatter,
headings, tables, code blocks, cross-links — so BM25F field weighting and the
edges plane both get exercised.

### 4.2 The 10 documents

| # | path | type | ~lines | hazard it plants |
|---|---|---|---|---|
| 1 | `docs/adr/0001-monorepo-build-graph.md` | ADR | 250 | term collision — "build", "graph", "index", "target" |
| 2 | `docs/adr/0002-deployment-gates.md` | ADR | 200 | **superseded** by #3; `status: superseded` + link |
| 3 | `docs/adr/0003-deployment-gates-v2.md` | ADR | 280 | **supersedes** #2; must outrank it on gate questions |

| 10 | `docs/notices/legacy-fleet-deprecation.md` | notice | 120 | short, dated, high-precision; owns "decommission date" |

**Hazard classes the goldens must cover** (§7.1 `hazard` field):

- `supersession` — #3 above #2, always.
- `near-duplicate` — #5 vs #6 disambiguated by fleet name.
- `attractor` — #8 must not beat the specific doc.
- `collision` — a query term that means different things in #1 and #4.
- `precision` — #10 wins on its one narrow fact.
- `edges` — a question answerable only by following #7's links.
- `no-answer` — 3–5 queries the corpus genuinely cannot answer.

Cross-links must be real markdown links so `ingest/edges.py` resolves `ref`
edges, and frontmatter `tags` must be present so `tag` edges exist. Verify
after ingest that a sample record's `edges` array is non-empty.

### 4.3 Writing rule

**Write the docs first, then the queries — never the reverse, and never
derive goldens from what fux actually returns.** A golden set fitted to
current output is a screenshot, not a test. For each query, decide the correct
answer by reading the corpus, then record it. If fux disagrees with a golden
you believe is right, **that is a finding for the report**, not a reason to
edit the golden.

### 6.1 `CLAUDE.md` for the playground

Short — one screen. It states the rules that keep the fixture honest:

- Edit a doc → re-run `python3 tools/check.py --all` → commit the index diff
  in the **same** commit. A doc change without its index change is a broken
  repo.
- Add a doc → add its queries. A document with no golden is untested weight.
- **Goldens are updated deliberately, never regenerated blindly** — the same
  rule `CLAUDE.md` in the engine applies to `tests_e2e/` golden files.
- Never commit an index produced by `--refresh-urls` (§8).
- The corpus is fictional. Do not make it resemble any real company's incident.

## 7. The harness

### 7.1 `goldens/queries.jsonl`

One JSON object per line, sorted by `id`, LF endings, no trailing blank line
issues. Schema:

```json
{
  "id": "q017",
  "query": "which deployment gate standard is current",
  "hazard": "supersession",
  "expect": [{"id": "file:docs/adr/0003-deployment-gates-v2.md", "max_rank": 1}],
  "forbid_above": ["file:docs/adr/0002-deployment-gates.md"],
  "top": 10,
  "note": "0002 may appear — it must never outrank 0003."
}
```

- **Grade on `id`**, not `title` or `loc` — `id` is the stable key
  (`AskResult` in `src/fux/query/scan.py` returns `id`, `title`, `loc`,
  `score`; `fux ask --json` emits `{"results": [...]}`).
- `expect[].max_rank` is 1-based. `forbid_above` means: must not appear at a
  better rank than the last satisfied `expect`.
- A no-answer query uses `"expect": []` plus `"expect_empty": true` — pass
  means `results` is empty **or** contains nothing from a `must_not_match`
  list. Decide which and be consistent; state the choice in `PLAYGROUND.md`.
- No scores in the goldens. Scores are an implementation detail; ranks are the
  contract.

### 7.2 `tools/check.py`

Stdlib only, Python ≥ 3.11. Modes:

- `--goldens` (default) — run every query, grade, print a per-hazard summary
  table and a per-failure detail block (query, expected, actual top-N).
- `--index-guard` — the staleness guard, §8.
- `--all` — both. This is what `CLAUDE.md` tells a contributor to run.
- `--verbose` prints the full ranking for every query.
- `--report <path>` optionally writes machine-readable results.

Exit non-zero on any failure. **Never** rewrite `queries.jsonl` — no
`--update-goldens` flag exists. If it is trivially regenerable it is not a
golden.

### 7.3 How the harness finds fux

`pyproject.toml` in the playground declares a dev dependency on the sibling
working tree:

```toml
[dependency-groups]
dev = ["fux-engine"]

[tool.uv.sources]
fux-engine = { path = "../fux", editable = true }
```

so `uv run fux ask "..."` from the playground root grades **the engine next
door**, which is the point: this is a regression net for the working tree, not
for a released package. `check.py` shells out to `uv run fux ...` with the
playground root as cwd (`find_root` needs it), and accepts `--fux` to override
the command. If `uv` or fux is missing, fail with a one-line instruction, not
a traceback.

## 8. The committed index, and the trap in it

**Decision: the committed index holds file documents only.** Zero `url:`
records. URLs are a runtime smoke test.

**The trap.** Read `src/fux/ingest/run.py`'s module docstring. A plain
`fux ingest` does not drop URL records — it **carries every existing `url:`
record forward byte-identically** (offline-by-default: reconciliation only
happens on a networked run). So once you run `--refresh-urls`, those records
are in `.fux/index/` and a subsequent plain ingest will not remove them. Commit
after a refresh and the "file-only" invariant is silently gone forever.

Therefore:

- `smoke_urls.py` **must** restore `.fux/index/` from git when it finishes,
  including on failure and on `KeyboardInterrupt`. Use `git checkout --` plus
  `git clean -fd` scoped to `.fux/index/`, then assert `git status --porcelain
  .fux/index` is empty.
- `check.py --index-guard` asserts the invariant directly: no line in any
  shard has `"src":"url"` or an `id` starting `url:`.

**The staleness guard**, in order:

1. Fail if `.fux/index/` is already dirty — the guard tests the committed
   bytes, so a dirty tree makes the result meaningless.
2. Run `uv run fux ingest`.
3. `git diff --exit-code -- .fux/index/`. Non-empty diff = the committed index
   does not reproduce from the committed sources. Print the diff and fail.
4. Assert the file-only invariant above.

This doubles as a determinism test: it is the byte-identical guarantee from
`CLAUDE.md` §"Non-negotiable constraints", checked on every run.

## 10. Non-negotiables

- **Offline by default.** Nothing in `check.py` touches the network. Only
  `smoke_urls.py` does, and only via `--refresh-urls`.
- **Byte-determinism.** The guard in §8 is the proof. No wall-clock anywhere in
  committed bytes.
- **$0 / stdlib-only** for both harness scripts. No `requests`, no `pytest` in
  the playground's runtime path.
- **Content is never durable outside its source system.** No URL snapshots,
  no cached page bodies committed. This is why URL goldens were rejected.
- **Hashed meta is the default.** The playground opts into `plain` explicitly
  because its URLs are public — and `PLAYGROUND.md` must **show** the
  difference: the record shape under `plain` (`title`, `phrases`) versus
  `hashed` (`title_h` only), with the one-line `fux.toml` edit that switches
  it. Document the switch; do not present `plain` as the norm.
- **Never edit `archive/`.**
- Doc style per `CLAUDE.md` §"Documentation style": short paragraphs, one idea
  per bullet, roomy.

## 11. Edge cases and known traps

- `gitdir.walk_sources` skips dotfiles and dotdirs — a doc under a `.`-prefixed
  path is silently invisible. Keep `docs/` clean.
- Shard count is fixed at 256; a 10-doc corpus lights up ~10 shard files. That
  is correct, not a bug — say so in `PLAYGROUND.md` so nobody "fixes" it.
- `meta = "plain"` only affects `url:` records. File records are always plain.
- On a `--refresh-urls` run, a **failed** fetch keeps the prior record rather
  than deleting it. `smoke_urls.py` must therefore distinguish "record exists"
  from "record was fetched this run" — compare `ver`/`sha` before and after,
  or start from an index with no URL records at all (preferred: it is the
  committed state anyway).
- Chrome must be reachable on **port 9299**, not the 9222 default in the fux
  repo's commented config. Set it in `[sources.url.config]` and say so in the
  README, including the launch flag a human needs.
- `fux ask --json` prints `{"results": [...]}`; an empty result set is
  `{"results": []}`, and the non-JSON path prints "No confident matches."
  Parse the JSON, never the human output.
