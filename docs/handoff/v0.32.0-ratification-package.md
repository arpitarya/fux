## Read this first — two things the tracker had wrong

Both were found while preparing this package, and both change what you are
actually being asked.

### 1 · `CLAUDE.md.proposed` does not exist. The rewrite is already the live file.

`docs/open/W-32` says adoption is *"mechanical: `git mv CLAUDE.md.proposed
CLAUDE.md`"*. **There is no such file.** The M0a rewrite was written straight
into `CLAUDE.md` — with a header declaring itself not in force — and has been
there since `3892c55` (2026-08-09).

Verified: the diff `v0.30.0-claude-md.diff` is `a/CLAUDE.md → b/CLAUDE.md.proposed`,
its a-side blob `4f52859` is the *pre-rewrite* file, and the live `CLAUDE.md`
is the b-side content. `git log --follow -- CLAUDE.md` shows no move.

**So the real question is not "adopt or not". It is:**

- **Yes** → delete the eight-line PROPOSED header. Nothing else moves.
- **No** → **revert ~800 lines** of the file every session reads first, back
  to the pre-reset version, and re-derive whatever of the last three days'
  guidance you want to keep.

Every session since 2026-08-09 — M1's gate, the T0 slice, the URL source, the
`.fux/` layout, the playground extraction, and this one — has followed the
rewrite as binding. That is not an argument that it is *correct*. It is the
reason "no" is the expensive answer, and you should know that before choosing.

### 2 · Two ADRs are shipped code sitting under unratified decisions

**ADR-0010 and ADR-0011 are not proposals.** Both are built, tested, released
in `0.30.0`, and load-bearing:

- The `.fux/` layout is what `fux ingest` writes on every run today.
- `.fux/sources/urls` and `.fux/middleware/cdp.py` are where the URL source
  lives; the sibling `fux-playground` repo copied that structure verbatim.
- ADR-0011's `derived_dir()` + `CACHEDIR.TAG` is the ground **M2 builds the
  accelerator on**, starting next.

A "no" on either is not a veto of a proposal. It is a request to change
shipped behaviour, and it becomes its own W-item with its own migration.

## Decision 1 · ADR-0001 — ingest-mode naming

**File:** [`../adr/0001-ingest-mode-naming.md`](../adr/0001-ingest-mode-naming.md)
· debate: [`../compare/ingest-mode-naming.compare.md`](../compare/ingest-mode-naming.compare.md)
· tracker: [W-30](../open/W-30-ratify-adr-0001.md)

**What is being ratified.** The two ingest modes are named **`extracted`**
(the default: `$0`, offline, deterministic) and **`enriched`** (opt-in,
model-assisted, deferred to M8). This replaces `inferred`, which collided
with `INFERRED` — the edge *grade* for model-derived edges. The collision is
the entire reason the ADR exists.

**What is already live under it.** The T0 slice writes `"mode":"extracted"`
semantics into every committed record. The word appears in `PLAN.md`,
`GLOSSARY.md`, `CLAUDE.md` and ADR-0004.

**What changes on a no.** A rename. Mechanical, and cheap *now* — the second
mode does not exist yet, so only one string and its prose are in play. It
gets more expensive at M8.

**After a yes:** ADR-0001 status → accepted · `adr/README.md` status column
updated. Two lines.

## Decision 2 · ADR-0010 — URL source via consumer-owned middleware

**File:** [`../adr/0010-url-source-consumer-middleware.md`](../adr/0010-url-source-consumer-middleware.md)
· tracker: [W-31](../open/W-31-ratify-adr-0010-0011.md)

**What is being ratified.** URL ingestion happens through a Python file *the
consumer owns and edits*, named in `fux.toml [sources.url]`. `fux ingest
--refresh-urls` is the only networked path; plain ingest stays offline and
carries existing `url:` records forward byte-identically. Hashed meta is the
default. **Core gains no adapter, no network code, no dependency** —
`src/fux/` still contains zero network lines, and the import fence test
enforces it.

**Why the shape matters.** It is how the three-adapter cap survives contact
with a real need: URL fetch became *configuration plus consumer code* rather
than core code. `[sources.url.config]` is passed to the middleware verbatim
and never read by fux — the PEP 518 `[tool.*]` discipline — which is what
keeps one middleware's vocabulary (`cdp_port`, `settle_ms`) out of fux's
config schema.

**What is already live under it.** Shipped in `0.30.0`. `.fux/middleware/cdp.py`
is in this repo and copied into `fux-playground`. Amended in place by ADR-0011
(paths moved into `.fux/`).

**What changes on a no.** Depends which part you reject. Rejecting the
*middleware shape* means designing a real adapter and breaching the cap.
Rejecting *hashed-meta default* re-opens a closed ACL ruling. Either is a new
W-item with a migration; neither is a revert.

**After a yes:** ADR-0010 status → accepted · `adr/README.md` column ·
`CHANGELOG.md` `[Unreleased]` drops the "⏳ proposed" qualifier.

## Decision 3 · ADR-0011 — the `.fux/` directory as a declared layout

**File:** [`../adr/0011-fux-dir-layout.md`](../adr/0011-fux-dir-layout.md)
· tracker: [W-31](../open/W-31-ratify-adr-0010-0011.md)

**What is being ratified.** Every child of `.fux/` is declared either
**committed** (`index/`, `sources/`, `middleware/`) or **derived**
(`runtime/`, `cache/`, `CACHEDIR.TAG`-tagged). Ingest writes a
self-describing `.fux/README.md` and a narrow `.fux/.gitignore` that lists
derived names and **never uses `*`**. `fux doctor` gains two checks.

**Why the `*` rule is load-bearing.** This repo's own `.gitignore` already
carried a `.fux/*` blanket that would have silently dropped `sources/` and
`middleware/` from git — no error, no warning, just a missing committed
plane. That is why `fux doctor` now asserts `git check-ignore` on the index.

**What is already live under it.** Shipped in `0.30.0`; written by every
`fux ingest`; and `derived_dir()` is the foundation **M2's accelerator is
about to be built on**. This is the one whose "no" is most expensive, and it
gets more expensive the moment M2 starts.

**One thing decided by the builder, not by you** — flagged deliberately.
ADR-0011 §Alternatives closes the original handoff's open question:
`.fux/README.md` is generated at **ingest** time, not by `doctor --fix`.
Reversible, and small, but it was your call to make and was made for you.

**What changes on a no.** A layout migration for anyone who has run `0.30.0`,
plus a re-plan of M2's derived-tier location before it is built.

**After a yes:** ADR-0011 status → accepted · `adr/README.md` column ·
`CHANGELOG.md` drops "⏳ proposed" · the four-line layout diff
[`v0.31.0-claude-md-layout.diff`](v0.31.0-claude-md-layout.diff) is applied
as part of Decision 4.

## Decision 5 · Who owns the ADR-numbering convention

**Tracker:** [W-33](../open/W-33-adr-numbering-contradiction.md) · prepared
diff: [`v0.32.0-adr-numbering.diff`](v0.32.0-adr-numbering.diff) (verified to
apply cleanly to the live tree)

**The contradiction.** `CLAUDE.md` says *"numbering continues at 0016"*, in
two places. [`adr/README.md`](../adr/README.md) says numbering **restarted at
0001** for the v0.30 rebuild — your call, 2026-08-09. **The files on disk
follow `adr/README.md`**: 0001–0004, 0010–0012.

### The two readings

| | **A · restart at 0001** *(what disk does)* | **B · continue at 0016** *(what CLAUDE.md says)* |
|---|---|---|
| live numbers | 0001–0004, 0010–0012 — unchanged | become 0016–0022 |
| collisions | two "ADR-0004"s exist (archived = agent integration; live = index format) | none, ever — a number identifies one document globally |
| disambiguation | the **"archived ADR-NNNN" + path** convention, which every live doc already uses | not needed |
| cost to adopt | **zero** — it is the status quo | a **third** renumbering of the same seven files, plus every citation |
| signal | the v0.30 line is a fresh start, which was the point of the reset | continuity with an engine that was deliberately abandoned |

**These files have already been renumbered once** (0016–0018 → 0001–0003 at
`6960237`), and frozen artifacts — the pre-registrations, conformance
evidence — still carry the *old* numbers with a note explaining the mapping,
because a frozen document is never edited. Reading B means a second such
layer of mapping on top of the first.

**Recommendation: A, and it is not close.** Disk follows it, you set it, and
B buys global uniqueness that the "archived ADR-NNNN" convention already
provides — at the price of a third renumbering and a second historical
mapping layer.

**The defect is not which policy. It is that the policy is written in two
places**, which is precisely how the two came to disagree. The prepared diff
fixes that: `adr/README.md` owns it, `CLAUDE.md` points at it.

**One thing the diff also records**, because it looks like a bug and is not:
ADR **0005–0009 are reserved** for M2–M6 and already cited by name in
`PLAN.md` and the `open/` DoDs, while 0010–0012 are taken. So M2's ADR is
**0005** — filling a hole, not appending.

**After a yes to A:** apply the diff (it covers both `CLAUDE.md` lines and
replaces `adr/README.md`'s "Unresolved for Arpit" block), then delete
`docs/open/W-33-*.md` and its row. If the rewrite (Decision 4) is also
accepted, apply both in the same change.

**After a yes to B:** it becomes a build W-item — renumber seven ADRs, rewrite
every citation, add the second mapping note. Do not let it ride along with a
docs commit.

**Nothing here blocks M2.** Every item is a decision that erodes the record
while it stays open — a permanently-⏳ ADR devalues the status column for
every other ADR, and shipped code under an unratified ADR means the tree and
the decisions disagree. That erosion is the cost of leaving them open, and it
is the only cost.

**What is riskiest about leaving these four open** is Decision 3. M2 builds
its derived accelerator directly on ADR-0011's `derived_dir()` and
`CACHEDIR.TAG`. Every day M2 progresses, a "no" on ADR-0011 costs more — and
after M2 lands it stops being a decision and becomes a rewrite.
