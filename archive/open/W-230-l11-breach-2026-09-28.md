# W-230 — the 2026-09-28 L11 breach, and the hooks that did not fire

## ✅ RULED 2026-09-28 (Arpit, Cowork) — no cost; fix the exec bit, gate it, probe live

*"go with the recommendation."*

**Cause found (Cowork, read-only, 2026-09-28):** `guard-golden-traversal.sh` is
`-rw-------` on disk and **`100644` in git** since W-223's commit `363a8b8c`;
the other eight hooks are `100755`. Claude Code launches a hook by path; a
non-executable file fails to launch, which is a non-blocking error, so the
command proceeds. The offline replays passed because they ran the hook through
`bash`. So the traversal guard has most likely **never fired live since W-223**;
the other two golden guards are executable and are presumed live.

1. **Cost: none beyond what is already `informed`.** Nothing from the key was
   printed and nothing was being measured; `set-4-claude` was scored before.
2. **Next, agent — a FRESH Claude Code session (Opus), not the one that caused

   - `chmod +x .claude/hooks/guard-golden-traversal.sh` and
     `git update-index --chmod=+x` on it.
   - **Gate (two strikes → a check):** a test that every hook registered in
     `.claude/settings.json` exists and is `100755` in `git ls-files -s`; the
     hook tests invoke each hook **by path**, never via `bash <hook>`.
   - **Live probe, after commit:** a Claude Code session runs
     `false && grep -rn probe work`. `false` short-circuits, so nothing walks

   - W-227 closes with this change once the probe is denied; W-230 closes with it.

## What happened

- I was appending W-227's regression tests to
  `tests/test_golden_traversal_guard.py` with a shell `cat >> … <<'EOF'`. The
  test text quoted the 2026-09-27 command, and that command contains a line that
  is exactly `EOF`. **The heredoc ended there**, and the lines after it ran as
  shell commands.
- One of them was the 2026-09-27 grep, verbatim:
  `grep -rn "open/W-226" work records docs src CLAUDE.md 2>/dev/null | grep -v "^work/golden"`.
  `work` was a root with no exclusion, so it walked `work/golden/`.
- **Printed:** two lines, both from `work/open/W-227-l11-breach-2026-09-27.md`
  (the breach file quoting that grep). **No answer text and no key file name
  reached the session.** `open/W-226` cannot occur in a key.
- The partial append was reverted (`git checkout` of that one test file).

## 🔴 The hooks did not fire, and this time that is not a guess

- At the moment it ran, `.claude/hooks/guard-golden-traversal.sh` was the
  **hardened** W-227 version (uncommitted, in the tree). Registration in
  `.claude/settings.json` is unchanged since 2026-09-27 18:16.
- **The same shape is DENIED offline**: fed to the hook on stdin, byte-for-byte
  replays of the 2026-09-27 command exit 2 under the normal `PATH` and a minimal
  one, and a heredoc body ending early and followed by the grep is denied too.
- **Live, it ran.** So the PreToolUse guard hooks are, in all likelihood, **not
  being executed for this Claude Code session's Bash calls** (VS Code extension,
  auto mode). That also explains W-227's live bypass, which offline replay
  could never reproduce. It means **all three golden guards may be inert in this
  session**, not only the traversal one.
- I did not probe further. A live probe (a recursive grep over a nonexistent
  `/tmp/…/golden`) was refused by the auto-mode classifier, and your W-227
  ruling authorises stdin-only replays.
