# W-244 — `fux ingest` lists the sealed key directory

**✅ CLOSED 2026-10-04 — built as ruled** (Claude Code, Opus). DoD 1: the walk prunes, a
spy on `os.scandir` proves the excluded directory is never scanned, and the block
names it once. DoD 2: this repo's index is byte-identical with the old and new
walk, 257/257 shards, and the root re-ingest wrote `work/golden/` as one line,
with 0 lines beneath it. DoD 3: seven root-walking tests use `tests/walk_lib.py`,
gated by `tests/test_walks_skip_golden.py`. DoD 4: SR-INGEST d24 and
SR-FUXIGNORE d11f, plus CHANGELOG. **`fux ingest` at this repo's root is safe again.**

**Model: Opus** for the fix, once ruled. It touches the walk every index is built
from and a law's enforcement, and a wrong prune silently drops documents.

## What happened (Claude Code, Opus, 2026-10-03)

- **The run.** W-168 step 8's removal (option (c), index v7) needs this repo's
  index re-ingested. The session ran `fux ingest --full` at the repo root. The
  tree was **LOCKED**: the `permissions.deny` rules are present and both guard
  hooks fired in this session.
- **The route.** `ingest/gitdir.py::_candidate_paths` walks each source
  directory with `Path.rglob("*")`, a filesystem walk that does not consult
  `.gitignore`. `.fux/sources/dirs` excludes `!work/golden`, so nothing under it
  is **read** (`read_bytes` is never reached), but every file there is
  **enumerated** and recorded as a skip, and the skips are written into the
  committed `.fux/.fuxignore`.
- **What reached the session.** `git diff .fux/.fuxignore` showed four new lines,
  the file names of the key directory, one per set, each marked `excluded by
  !work/golden`. **No file content, no answer text, no evidence quote, no
  `relevant` / `primary` name and no `answerable` flag.** Only the four names.
- **Why it had not shown up before.** `HEAD`'s `.fuxignore` names nothing in that
  directory, so the last committed ingest ran while it held no files. The session
  did not investigate further, because doing so means naming the directory, and
  `guard-sealed-key.sh` correctly refused a `git log -S` that named it.
- **Contained.** The working-tree `.fux/.fuxignore` was restored to `HEAD` before
  any commit. A concurrent session is active in this tree and a `git commit -a`
  would otherwise have carried the names. **No commit on any ref holds them.**
- **The re-ingested `.fux/index/` is clean.** Excluded paths produce no record,
  so no record `id`, `loc` or edge `dst` in `.fux/index/` is under
  `work/golden/` (checked by a grep of `.fux/index/` alone).

## Why it is L11's business

L11 forbids any agent to list anything in the key directory, and requires a
recursive walk over `work/` to exclude `work/golden/` in every state. A program
that walks on its own is the route L11 decision 9 names as *"still prose"*.
**This is that route, and it is now writing what it finds into a committed
file.** The names are not key bytes, so *never committed* is not breached, but
they were one `git commit -a` away from a committed ref.

## For Arpit — the minimum question (as filed; the ruling is below)

**Cost and fix: is this `informed`-only, as W-223/W-227/W-230 were, and may the
ingest walk prune an excluded directory instead of enumerating it?**

- **Recommended fix (Opus, one change):** `_candidate_paths` never descends into
  a directory that a source exclude (`!pattern`) already removes. The skip list
  then records `work/golden/` **once, as a directory**, not file by file. This
  changes what `.fuxignore`'s generated block contains, which is
  [SR-FUXIGNORE](../../records/0144_fuxignore.md)'s and
  [SR-INGEST](../../records/0106_ingest.md)'s to decide. That is why it is asked,
  not built.
- **Alternative:** enumerate from `git ls-files` + untracked-not-ignored, so a
  gitignored directory is never walked. This is broader: it changes which
  untracked files ingest sees.
- ⚠ **The unit suite has the same shape.** Several repo tests `rglob` from the
  repo root (`test_doc_links.py`, `test_archive_law.py`, `test_claude_md_*.py`,
  `test_record_paths_resolve.py`). Their skip sets do not name `golden`, so they
  enumerate the directory too, though they print nothing from it. The fix should
  cover them in the same change: add `golden` to each skip set and a test that
  fails if a walking test omits it.
