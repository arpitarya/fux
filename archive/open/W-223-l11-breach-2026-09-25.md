# W-223 — the 2026-09-25 L11 breach

**Model: NONE.** This is a ruling, not a build.

🔴 **Declared under [L11](../../records/0012_LAW-11-sealed-answer-key.md)** by

[WORKLOG](../WORKLOG.md) entry of 2026-09-25, *"L11 BREACH DECLARED"*. This file

## What happened

- A `grep -rln "W-222"` from the repo root excluded `.git` and `archive` and
  dropped golden-tree lines from the **output** with `grep -v`. The traversal
  itself still read every file under the golden tree, **key directory included**.
- Two plain `ls` calls of the golden tree's parent showed the key directory's
  entry name. Nothing inside it was listed.
- **No answer text and no filename from the key directory reached the context.**
  `W-222` cannot occur in a key, so nothing matched there.

## What it touches

- The `2026-09-25-rm3-boosted` capture finished **before** the grep. Its numbers
  are `informed` regardless, because `set-2-u` is Claude-authored.
- **The guard gap:** neither the deny rules nor the guard hook see a recursive
  command that never names the key directory. L11 already names this route as
  the one no guard sees.

## 🔴 What Arpit decides

1. Whether the breach costs anything beyond what is already `informed`.
2. Whether the recursive-traversal route gets a mechanical guard (for example a
   hook that rejects `grep -r` / `rg` / `find` over `work/` or `.` without a
   golden exclusion), or stays covered by prose, as L11 has it now.

## ✅ Question 2 RULED and BUILT 2026-09-27 (Arpit, Cowork) — *"implement the hard guard"*

- `.claude/hooks/guard-golden-traversal.sh` refuses a recursive walker
  (`grep -r`, `rg`, `ag`, `ack`, `fd`, `find`, `tree`, `ls -R`) whose root can
  reach `work/golden/` and that has no golden exclusion. That covers the repo
  root, `work/`, `work/golden/`, `..`, `~`, an absolute ancestor, or no path
  while cwd is one of those.
- It is registered in `.claude/settings.json`, named in
  `tools/golden-switch/switch.py` `HOOK_NAMES` (so `golden-unlock` and
  `golden-lock` move it with the other two), and checked by `just golden-guards`.
- Pinned in both directions by `tests/test_golden_traversal_guard.py`: 16 denied
  (the 2026-09-25 command first) and 20 allowed, plus fail-closed, a non-shell
  tool, and registration.
- L11 decision 9 and door 3 are amended, and so is SR-WORK-GOLDEN (the guard
  list, the routes bullet, and the refused alternative now overruled in a
  narrower form).
- ⚠ **Still prose:** a program that walks on its own, and a path built at runtime.

**Question 1 is still open:** whether the breach costs anything beyond `informed`.
