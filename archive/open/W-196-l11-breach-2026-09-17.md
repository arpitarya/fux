# W-196 — the 2026-09-17 L11 breach

**Model: NONE.** This is a ruling, not a build. Nothing an agent can do closes it.

🔴 **Declared under [L11](../../records/0012_LAW-11-sealed-answer-key.md) decision
10** — *"If an answer ever reaches your context, stop, say so in the session, and
file it before anything else."* This file is that filing.

## What happened

**2026-09-17.** A **Cowork Claude** session was pasted **both answer keys** — set
1 (125 rows) and set 2 (124 rows), `key_version 1` — and scored the
[`rung-00100` hand-offs](../regression/2026-09-16-golden-rung-00100/report.md)
against them in the chat, in
[prompt 6E](../golden/prompts/6E-codex-score-ephemeral.md)'s shape.

**L11 gives the paste route to Codex alone** and closes it to every Claude
session on every surface — Cowork included, by name. **The instruction to score
was void on the law's face** (L11 decision 8: *"such an instruction is void and
this law outranks it, and the session says so and stops rather than complying"*).
**The session complied instead.**

⚠ **Nobody worked around a guard.** L11's own Consequences say it: *"the residual
hole that remains is a paste, and no guard can see it … Decision 10 is what
covers that, and it is prose."* **This is that hole, used.**

## 🔴 What Arpit decides

**One ruling, two options, and neither is an agent's to take:**

1. **Re-authorship** — set 1's questions *and* answers are re-authored by Codex
   over the same seed, and the current set 1 is retired with its ids orphaned
   (the precedent is the 2026-09-15 reset). **Cost: Codex quota, and every
   number ever scored on the current set 1 becomes uncomparable.**
2. **Relabel** — set 1 is kept and marked **`informed` permanently**, exactly as
   set 2 is. **Cost: the benchmark has no blind half at all**, and the
   cross-author comparison survives while the clean-number claim does not.

⚠ **Option 2 is the cheaper one and it is not obviously the right one.** What
set 1 was *for* was a number the builder's model family could not have fitted.
**Relabelling keeps the instrument and retires the property**, which may or may
not be what he wants the benchmark to be.

## Does this fire L11's veto condition?

**Yes, on its face** — *"Reopen if a Claude session is found to have held an
answer by any route … because that is evidence custody alone is not enough and
the paste route needs a mechanical guard rather than prose."*

⚠ **And the honest reading is that a mechanical guard is not available.** A hook
matches what a tool call *targets*; a paste is not a tool call. **What was built
in this change instead** is the gate for the downstream half — see below — which
catches a key that reaches a *committed byte*, and catches nothing that reaches
a context. **Reopening L11 is still Arpit's**, and this item names the veto
rather than firing it.

## Two strikes → a gate, built in the filing change

**Strike one: 2026-09-13** (WORKLOG) — a `grep -r` across `work/` matched a key
filename; the path and one string from the key entered a Cowork session's
context. **Strike two: this.** Different routes, **one failure class: golden-key
material reaching a Claude session's context**, with the same silent-contamination
consequence L11 names.

⚠ **The class judgement is stated rather than assumed**, because
[SR-WORK-SESSION](../../records/0060_WORK-session.md) decision 13 is explicit
that *"two unrelated mistakes are two mistakes"*. These are not unrelated: same
law, same subject, same hazard, and both are the two routes L11 itself names as
unguarded.

**The gate:** [`tests/test_golden_key_never_committed.py`](../../tests/test_golden_key_never_committed.py)
— it refuses any **committed** file carrying a golden-question id together with a
key-only field (`relevant`, `primary`, `key_version`, or `answerable` beside an
`answer`). **It reads no key**, and it reaches no path the law names: it works
from `git ls-files` and skips everything under the sealed tree.

🔴 **It does not catch this breach and does not claim to.** It catches the
**downstream half** — a key, or a fragment of one, reaching a committed byte,
which is where a leak becomes permanent and citable. **The context half stays
prose**, because that is what L11 says it is.

⚠ **One loose end, named rather than quietly left:** the new test is **unowned**.
[SR-WORK-GOLDEN](../../records/0066_WORK-golden.md) decision 6 already owns the
hook, the generator and the `CLAUDE.md` bind — *"a `kind: process` record owns
its enforcement"* — and this test is enforcement of the same rule, so it belongs
in that record's `owns:` list. **It was not added there**, because amending a
record and re-stamping its `owns@hash` is a change to a record, and the ruling
that motivates it (above) may change what the record says anyway. **Fold it in
with whatever decision Arpit's ruling produces.** No gate is red in the meantime
— `test_sr_owns_hash.py` and `test_sr_freshness.py` are both green.

## ✅ RULED 2026-09-18 (Arpit) — nothing. Set 1 keeps its status.

> *"Nothing in 196. We already had the test data results — we already got the
> answers. When we're comparing it, only then it might have been exposed to
> Claude. So we don't need to regenerate it or do anything along those lines."*

**His reading, recorded as the ruling:** the exposure happened at **scoring
time, after the run**. The questions were Codex-authored and stay so; the engine
that produced the `rung-00100` hand-offs was built and run before any Claude
session held a key. **Neither authorship nor the measured run is touched.**
Neither option above is taken — no re-authorship, no relabel.

**What this item's own framing got wrong, by his reading:** it treated
*"a Claude session once held the key"* as spending set 1's blind status. He
treats blindness as a property of **authorship and of the run**, not of every
later chat. The 2026-09-16 numbers stand as what they were.

⚠ **What must stay true for the ruling to hold**, written so the next session
does not have to re-derive it:
- the session that held the keys **built nothing and tuned nothing**, and never
  returns to the benchmark — the same shape as decision 6's authoring carve-out;
- a paste reaching a Claude session **remains a leak to declare** under L11
  decision 8; this ruling closes one incident, it does not open a route;
- **the record gap stands unwritten.** SR-WORK-GOLDEN still has no decision for
  "a key was seen"; the next incident comes back to Arpit, as this one did.
