### 🔴 2026-08-27 — the hold was right, and here is what was under it

**`_sweep` never reached the ingest. Not once, in any repository.** Found by
running the full unit suite in an environment that could run it (Cowork,
Python 3.11.15, editable install), as a follow-on from
[W-87 P5](W-87-what-good-means.md).

    from ..ingest import run as ingest_run     # binds a FUNCTION
    ingest_run.run(root, refresh_urls=True)    # AttributeError, always

`fux/ingest/__init__.py` re-exports the function `run` from the submodule of
the same name, so that import binds the function and the attribute access
raises. ⚠ **The broad `except Exception` that makes a daemon outlive one bad
sweep turned that into `"failed"` — every sweep, forever.** The daemon started,
wrote its pid file, wrote its status, slept its interval, and indexed nothing.

⚠ **The test that should have caught this patched the same wrong object.** It
failed on its own `monkeypatch` line, so it never once exercised the
failing-sweep path it is named for. **A test written from the same
misunderstanding as the code is not a check.**

- [x] **Fixed** — `import_module("fux.ingest.run")`, which cannot be shadowed
      and is also what lets a test patch `fux.ingest.run.run` and have the call
      see it.
- [x] **Gated** — `tests/maintain/test_daemon_sweep_reaches_ingest.py`: a
      healthy sweep returns `ok`, **the index actually contains the document**
      (a return value cannot prove work happened when every exception is
      swallowed — that is precisely how this hid), the patch seam works, one
      bad sweep still returns `failed`, and **no module in `src/` may use the
      shadowed import shape again** — checked with `ast`, because this shape
      has now cost three separate defects in one day.
- [x] **Verified by hand**: `_sweep` returns `"failed"` before the change and
      `"ok"` after, in a repo with `[sources.url]` declared.

⚠ **This does not discharge the hold.** What Arpit asked for is
`start` → wait → `status` → `stop` **in a real repo with URLs** — a detached
process, a real clock, a real network. What this establishes is that the sweep
now does its work at all, which it did not before, and that the run would have
been worth doing on the very first attempt.

⚠ **Two things this surfaced and did NOT fix**, both judgment calls:

1. **A misconfigured repo fails silently forever.** `_sweep` returns `"failed"`
   for a `FuxError` about `max_parallel` exactly as it does for a dead network,
   and the status file records the outcome **with no reason**. A user sees
   `failed` and has nothing to go on. Widening the status shape is an
   `state.schema.json` change and is not an agent's call.
2. **The re-export in `fux/ingest/__init__.py` is the root cause.** Renaming it
   would remove the trap at the source rather than guarding each site, but it
   is an API change across the codebase.

## ✅ The daemon (ruling 10) — BUILT 2026-08-27, and veto 6 fired and answered

**Arpit's spec, 2026-08-27:** *"like a dev server. `fux daemon start`, so it
keeps running, and `fux daemon stop`. The code only lives inside the project,
not globally."* Plus two design rulings: it **writes `.fux/index/` directly,
taking `runner.lock`**, and sweeps on a **fixed configurable interval**.

**Shipped:**

| | |
|---|---|
| `src/fux/maintain/daemon.py` | the module — start · stop · status · serve |
| `fux daemon start\|stop\|status` | a flat verb like `mcp`; the action is positional, not a subparser |
| `[sources.url] sweep_minutes` | default **60**, in `config.py` |
| `tests/maintain/test_daemon.py` | the guards below |
| ADR-MAINTENANCE **decision 11 / 11a–11d** | the record, and veto 6's answer |

**Veto 6 was FIRED, not declared out of scope**, and is now marked **SPENT**
alongside condition 1. What survives in it: *"the detached **runner** turns
into"* — the runner must stay one-shot, and the daemon's existence buys it
nothing.

⚠ **The compare verdict is reopened rather than overridden silently.**
`maintenance-trigger.compare.md` rejected the class; its own consequences
already said a watch daemon *"would be its own proposal if revisited"*, and the
subject differs — that verdict governs how a **local source edit** reaches the
index, this governs how a **remote URL change** is noticed.

⚠ **The honest cost, accepted rather than argued away:** fux now owns a
lifecycle — start, stop, crash, laptop sleep, double-run, stale build after an
upgrade. §4.1 rated confidence on shipping C *medium* and warned the cost must
not be minimised by pointing at `runner.py`. It is not minimised here.

**What the tests actually guard** (a daemon's real failures are not the usual
unit-test ones):

- **`sys.executable -m fux.cli`** — the interpreter already running, so the
  project `.venv` is pinned rather than looked up on `PATH`. *"Inside the
  project, not globally."*
- **No launchd plist, systemd unit, crontab or global install** — checked over
  the module with comments and string literals stripped.
- **Never signals** — `stop` is a file the loop polls, and a `timeout` is
  reported, never escalated. A signal inside `write_index` leaves a partial
  shard.
- **One lock, not two** — `runner.acquire`, released in a `finally`, and the
  sleep sits outside `_sweep` so an hour-long hold can never block `fux ingest`.
- **Status never mutates** — a stale pid file reads as *not running* and is left
  on disk (veto 7).
- **Nothing starts it but a human** — asserted against `setup.py` and every hook
  body. **That consent is the whole of veto 6's answer, so the moment something
  else starts it, the answer is void.**

⚠ **One defect this produced and then caught, worth carrying:** the first
version of the outside-the-repo and no-signal guards did a bare substring check
over the module source — and **failed on the module's own docstring**, which
explains the constraint by naming `systemd` and `SIGTERM`. A module was being
punished for documenting itself, and the tempting fix is to delete the
explanation. `_code_only()` strips `COMMENT` and `STRING` tokens instead.

**ADR-MAINTENANCE veto condition 6**, accepted and live:

> **The detached runner turns into something always-on** — a resident process,
> a scheduler, or a watcher. That is option C from

**The case that the veto does NOT fire, stated fairly:**

- **Different subject.** `maintenance-trigger`'s option C is a *filesystem
  watch daemon* that re-ingests on every file save — its question is how a
  local source edit reaches the index. Ruling 10's daemon is a **URL freshness
  clock**. Neither watches the filesystem; neither re-ingests on save.
- **Different process.** Veto 6's subject is *"the detached runner turns into"*
  something always-on. A separate clock process is not the runner changing
  shape.
- **The compare doc left the door open:** *"A watch daemon (C) is not
  eliminated forever… **would be its own proposal if revisited.**"* That is a
  revisit path, not a permanent refusal.

**The case that it DOES fire:**

- The veto's plain words are **"a resident process, a scheduler, or a
  watcher"** — three nouns, no qualifier about *which* subject it schedules.
  A URL clock is a scheduler by any reading.
- The compare doc's stated objection to C was *"requires an always-on
  background process this codebase has never needed before"*. That objection is
  about the **class of thing**, and it transfers intact.
- §4.1's own confidence on shipping C now was **medium**, and it warned that
  *"C's cost must not be minimised by pointing at `runner.py`"* — start, stop,
  crash restart, laptop sleep, double-run, stale build after upgrade.

**⚠ An agent may not pick between these.** A veto condition is a condition to
check, and this one is at minimum arguably true. What is owed from Arpit:

1. **Fire-and-answer veto 6 explicitly** — like condition 1, which is marked

2. **Reopen `maintenance-trigger`'s verdict**, or record why a URL clock is

**Until then the daemon is not built, and ruling 3 (narrow-by-default) must not

## 2 · `tune.toml` — `[bm25f]` drops the `_weight` suffix

**Ruled:** inside `[bm25f]`, the five field weights are named for their fields.

```toml
[bm25f]
k1 = 1.2
b = 0.75
body = 1.0
heading = 3.0
title = ...
path = ...
ctx = ...

[ranking]
archived_weight = 1.0
superseded_weight = 1.0
rerank_weight = 0.0
```

- **Why:** inside a table already named `bm25f`, the suffix is noise, and `k1`
  and `b` already carry no suffix — the table was internally inconsistent.
- **`[ranking]` keeps `_weight`**, where it genuinely disambiguates.
- **Consequence:** `_FIELD_KEYS = tuple(f"{name}_weight" for name in TF_FIELDS)`
  collapses to `tuple(TF_FIELDS)` in `src/fux/tune.py`.
- ⚠ **Breaking for anyone on `v2.0.0-alpha.1`.** Alpha, so it is taken now
  rather than never; it needs a CHANGELOG break note and a config error that
  names the old key and the new one.
- **Then** ADR-TUNE flips `proposed` → `accepted`, freezing the names.
- **Record:** `docs/adr/0038_tuning.md`.

## 3 · The narrow refresh is the default; `--all` overrides

**Ruled:** no `--dirty` / `--stale` / `--changed` flag. `fux update` refreshes
the dirty list; `fux update --all` forces the full sweep.

- **Why:** if the dirty list is the right thing to refresh, it should not have
  to be asked for. A user typing `fux update` wants a current index, not a
  network sweep.
- ⚠ **This is a behaviour change to a shipped verb**, free now and a
  deprecation cycle once anyone scripts it.
- ⚠ **It raised the stakes on the clock** (ruling 10): with narrow as the
  default, the **tail is never refreshed** unless something else sweeps it.
  Ruling 10 is what covers that, and the two must land together or the tail
  silently stops being refreshed at all.
- **Records:** ADR-URL-INGEST · ADR-MAINTENANCE.

## 10 · The clock is a daemon

**Ruled:** option **C**. Fux ships a local daemon as the clock for the tail.
**No CI workflow template ships.**

⚠ **§4.1 rated confidence on this only *medium*, and its warning stands: C's
cost must not be minimised by pointing at `runner.py`.** What is now owned:

- **A full lifecycle** — start, stop, restart on crash, log somewhere, survive
  a laptop sleeping, never run twice, never run as a stale build after an
  upgrade. `runner.py::acquire` solves the **locking** half and none of the
  **operations** half.
- **Stdlib only (L1)** — no supervisor dependency, and **a Windows story from
  day one**, since Windows-first fleets are a stated design input under
  CLAUDE.md §Litmus. Not a unix double-fork.
- **The L4 opt-in must stay visible** — an explicit start command, **never**
  auto-started by `fux setup` or by install. §4.1's mid rating of C's consent
  assumed a daemon the user chose to run.
- **The daemon never commits** — dirty list and `.fux/runtime/` only, or L3
  breaks.
- ⚠ **What this closes:** a team whose CI *can* reach the sources now runs a
  laptop daemon instead of a reviewed workflow file. D was rated the strongest
  opt-in of the four *and it is not close* — that option is now shut.
- **Record:** ADR-MAINTENANCE amendment, or a new record for the clock.
- **§4.1's reopen triggers still apply** and are unchanged by this ruling.

## 11 · Hooks never touch the network

**Ruled:** fork 2 is **no**. The `post-commit` hook does not fetch, not even
for the commit that edits `.fux/sources/urls`.

- **The invariant, and it is testable in one line:** no hook path may reach the
  fetcher.
- **`fux add <URL>` still fetches** — an explicit command is not a hook.
- **Consequence:** URLs added by hand-editing the sources file wait for the
  daemon's next pass or an explicit `fux update`.
- **Why:** the cleanest L4 story available, and it removes the consent mismatch
  §4.1 described — a colleague who runs `fux hooks --install` once should never
  thereby send traffic to hosts they never chose.

## 12 · On a 429 — back off, retry, report; never mutate the cap

**Ruled:** exponential backoff for that host, retry, and record the event in
the URL health report so `fux doctor` can say *"this host rate-limited you 12
times — consider lowering `max_parallel`."*

- **The configured cap is never changed by fux**, not even for one run. This is
  the standing rule: state the cost, do not clamp the knob.
- **Not chosen:** auto-lowering the effective cap (the concurrency becomes a
  number the user did not pick and cannot predict); failing the URL outright
  (one busy minute marks healthy documents stale); reading `Retry-After` (HTTP
  semantics fux deliberately stays out of).
- **Today `urlsrc.py` only *warns* that 429 may happen and does nothing when it
  does.**
- **Records:** ADR-FETCHER · ADR-URL-INGEST.

## 13 · `copilot` stays

**Ruled:** `KNOWN_AGENTS = ("claude", "copilot", "kiro")` is unchanged, and
copilot remains installed by default.

- It already has both renderings — `fux-archived-results.instructions.md` and
  `fux-usage.instructions.md`.
- **Dropping it would need a mechanism fux does not have:** `fux setup` writes
  and keeps; it never deletes. Removal would strand files in every repo already
  set up.
- A consumer who does not want it already has `[agents] install`.

## 14 · `python -m fux` becomes a supported entry point

**Ruled:** add `src/fux/__main__.py`, delegating to `fux.cli`.

- **Why:** the ladder's last rung should be the spelling a human guesses.
  `python -m fux.cli` works and is what `tests_e2e/` spawns, but nobody types it.
- **A thin delegate is not really a second implementation** — a test asserts
  `python -m fux` and `python -m fux.cli` produce identical output.
- **Record:** ADR-CLI · ADR-AGENT-POLICY (the ladder's rung 4 wording).

## 15 · Policy is steering; operating manuals are skills

**Ruled:** the split the build made for Kiro is **the rule**, not a one-off.

| kind of guidance | rendering | why |
|---|---|---|
| must shape every answer (archived-results policy) | steering, `inclusion: always` | an agent not thinking about fux still must not cite an archived doc as evidence |
| consulted when doing a thing (how to invoke fux) | skill, loaded on demand | no reason to tax every interaction |

- ⚠ **Kiro CLI has no inclusion modes** — every steering file loads on every
  interaction, so steering is a permanent context tax on every developer in the
  repo. That is what makes this a rule worth stating rather than a preference.
- **Write it into ADR-AGENT-POLICY** so the next rendering's placement is
  automatic rather than a judgement call.

## 16 · A repo-root `AGENTS.md` is written

**Ruled:** yes. ⚠ **Three consequences, and the first is a live tension with
ruling 15:**

1. **It must stay policy-shaped and short.** Ruling 15 says ambient files carry
   policy, not manuals — and Kiro loads `AGENTS.md` on every interaction. So it
   carries the **invocation ladder** (five lines) plus the archived-results
   rule, and **points at** the `fux-usage` skill rather than inlining it.
   Otherwise the two rulings contradict.
2. **`_write_if_missing` makes the coverage absent exactly where it is needed.**
   A repo with a hand-written `AGENTS.md` gets nothing and no error.
   **ADR-AGENT-POLICY decision 6 requires the announcement** — setup says it
   skipped, and prints the snippet to paste.
3. **It has no vendor.** `AGENT_FILES` is keyed by vendor; a repo-root neutral
   file needs a slot outside that map, or all three vendors race to write it.
4. **ASCII only** — ADR-CLI veto 7.

## 17 · ADR-RS decision 12 stands as written

**Ruled:** the scope defect is **not repaired**. An informed run keeps
disclosing the conflict, as the first run under the rule honestly did.

- **The defect, restated so it is not rediscovered:** decision 12 says an
  informed run *"never supplies a delta"*, and the first run filed under the
  rule was informed by construction and made **entirely** of deltas — a wheel
  30× smaller, an index 22.6 % smaller, an ingest 6.8× faster. **As written the
  rule forbids reporting a file size.**
- ⚠ **Record in ADR-RS that this is known and deliberately unrepaired**, and
  that disclosure is the sanctioned response — otherwise a future session
  "fixes" it and quietly narrows a measurement rule nobody asked to narrow.
- **Not chosen:** narrowing to evaluation-set metrics only; a separate
  declaration axis for performance numbers.

## 18 · The coherence gap is stated, and filed

**Ruled:** write the limit into CLAUDE.md plainly, and file the item. **No new
mechanism.**

- **The gap:** `tests/test_adr_freshness.py` checks a record was **touched**,
  never that it is **coherent**. In W-83 an accepted amendment contradicted
  itself, the code implemented the wrong sentence, and every mechanical check
  fux has passed.
- **The wording owed in CLAUDE.md:** the freshness gate proves a record was
  edited and proves nothing about whether the edit is self-consistent — so Law
  zero's *"re-read the records you touched code under"* is the only thing
  covering it, **and it is unenforced.**
- **Why no mechanism:** the two-strikes rule fires on a class's **second**
  recorded occurrence. This has happened once. Filing it is what makes the
  second occurrence visible as a repeat.
- **Not chosen:** a model-based coherence check in CI (noted as *not* an L3
  violation, since L3 governs the index maintenance path and CI is not that
  path); forced whole-block rewrites of amended decisions.

### Hunk 1 — ruling 18, the coherence gap

Append to **§Law zero**, after the "This is enforced, not trusted" paragraph:

```markdown
**⚠ What the check does NOT prove, and nothing else does either.**
`tests/test_adr_freshness.py` proves an owning record was **touched** in the

code implemented the wrong sentence, green the whole way.

**So point 3 above — re-read the records you touched code under — is the only
thing covering coherence, and it is unenforced.** Treat it as the obligation it
```

### Hunk 2 — ruling 9, links into `archive/`

Replace, in **§Archive is not evidence**, the paragraph beginning *"When
repointing a citation away from an archived doc"* — **keep that paragraph** and

```markdown
**A link is not a citation** (Arpit, 2026-08-27). Prose naming an archived item
— *"W-52's trigger"*, *"superseded by X"* — may link to it, including from a
Reference block. This rule governs where a claim is **grounded**, never whether
```
