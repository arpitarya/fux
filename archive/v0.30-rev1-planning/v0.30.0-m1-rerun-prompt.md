# Claude Code prompt — v0.30.0 M1-rerun

*Run with **Opus**. The last attempt failed at measurement design, not at
coding — that is the part that needs judgment.*

---

You are re-running Fux's pruning gate (P1) so that it actually tests the
thing it claims to test. The full spec is
`docs/handoff/v0.30.0-m1-rerun-handoff.md` — **read it first and treat its
Definition of Done, Scope, and Non-negotiables as binding.**

Start by reading `docs/adr/0002-pruning-eval-gate.md` in full. A previous
run returned INCONCLUSIVE and explained precisely why: the eval documents
have 32–46 distinct terms, so "keep the top 128" removed nothing, and a
delta of 0.00 over an untreated population is not evidence. That ADR is the
standard for this work. **Your job is to produce a result that is
trustworthy, not a result that is positive.** A second INCONCLUSIVE, or a
FAIL, honestly argued, is a good outcome.

Three things changed since that run, and they are the point of this one:

1. **The metric.** Fux ranks in the index, fetches the top-k, then
   re-scores passages on the fetched text — so the index is a *candidate
   generator*, not the final ranker. The gate is **recall@20**, not hit@5.
2. **The criterion.** KL divergence penalises terms that are common across
   the collection, which in a topically homogeneous corpus means it deletes
   the document's own subject (it dropped `webhook` from `webhooks.md`).
   Five arms now compete, including a combined selector.
3. **The budget.** Retention (~6 %), not a fixed k — so the treatment means
   the same thing on a short note and a long specification.

## Task — five phases, in order, and phase 1 can stop the whole thing

**Phase 1 — the corpus, and its gate.** Acquire a long-document corpus
(recommended: the RFC corpus — ~9 500 technical documents, 10³–10⁴ words,
public, stable). Fetching is a *lab* activity; pin a manifest of
`(id, sha256)` so every later run reads the local copy. Build an eval set
and **document its construction and its bias honestly** — heading-derived
queries flatter Rule A, and the ADR must say so.

Then report the distinct-terms-per-document distribution **before running
any arm**. If the median is below 500 distinct terms, **STOP and tell me** —
the corpus cannot exercise 6 % retention, and continuing would reproduce
exactly the failure ADR-0002 caught. Do not substitute synthetic data if
the fetch is unavailable; stop and report.

Also prepare the second corpus: the repo's own long-form docs plus
`archive/v0.26-docs/`. It is small but it is the actual target domain.

**Phase 2 — the selector.** Implement Rules A (heading spine), B (impact
budget) and C (per-term backstop sweep) exactly per the compare doc §7,
with the adaptive budget `max(floor, share × vocab)`. Two things invalidate
the run if you get them wrong: **Rule C runs after every document's local
pass**, and **`df`/`n`/field-lengths are recomputed after Rule C** over the
final kept postings — never borrowed from the unpruned index.

**Phase 3 — pre-register, then freeze.** Write
`tools/pruning-eval/PRE-REGISTRATION-v2.md` with the five arms, the three
retention rungs, recall@20 as the sole gate metric, the PASS/PARTIAL/FAIL/
VOID rule from handoff §5.4, and the compare doc's stated prediction
(arm 4 ≈ arm 5 at 6 %; arm 1 the outlier). **Commit it before the first
gating number exists.** Pause here and show me the pre-registration and the
corpus statistics before running the arms.

**Phase 4 — run.** Five arms × three rungs × both corpora. Report actual
retention and prune coverage per cell — a cell whose coverage is near zero
is void by construction. Produce the failure catalogue for every arm that
drops a gold document out of the candidate set.

**Phase 5 — the verdict.** Write `docs/adr/0003-pruning-criterion-rerun.md`:
the numbers, the selector decision, and PASS / PARTIAL / FAIL / INCONCLUSIVE
against the frozen rule. File evidence under
`docs/conformance/<date>-pruning-rerun/` with a reproduce command that
actually reproduces. Update the compare doc's verdict block, OPEN-WORK, and
add a one-line forward pointer to ADR-0002 — **do not rewrite ADR-0002**; it
is the record of a correct refusal.

## Constraints (hard)

- **Stdlib only** — in the selector *and* the harness. No numpy, pandas,
  scipy. The selector must port into `src/fux/ingest/` unchanged.
- **Deterministic** — sorted iteration, ties on doc id, fixed seeds, no
  wall-clock in output. Two runs → identical `report.md` sha256.
- **Do not modify `archive/`.** Wrap or monkeypatch from the harness.
- **Do not modify** `docs/paper/`, or any compare doc verdict except
  `pruning-criterion`'s.
- **Build none of M2–M6, and do not create `src/` or the M0b scaffold** —
  even on a clean PASS. The scaffold is a separate execution.
- **Do not build** the Bloom "recall insurance" plane (priced out), the
  query-view Rule D (post-M7 proposal), or anything model-dependent.
- **Never move the threshold after numbers exist.** Ambiguous results get
  written up as ambiguous.
