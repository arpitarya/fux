```

READ: work/handoff/v0.32.0-open-items-handoff.md §4, work/open/W-22-m2-t1-accelerator.md,

BUILD W-22: a derived, blocked term-major JSONL accelerator under .fux/runtime/
(derived plane, CACHEDIR.TAG per ADR-FUX-DIR) that makes warm `ask` fast WITHOUT
CHANGING A SINGLE RANKED RESULT.

  - blocked term-major JSONL + offset table; 128-posting block lines with integer
    `mx` skipping (the measured close of the common-term trap, 397ms -> 44ms)
  - int-cached Hamming lane over the existing FuxVec 32B `code` property
  - RRF fusion (k=60), PORTED from archive/v0.26/ WITH ITS TESTS — port, don't rewrite
  - `find` and `answer` verbs
  - rebuild path: derived, never committed, reconstructible from the committed shards ALONE

THE DIFFERENTIAL LAW — the part that must not be got wrong:
accelerator results are IDENTICAL to scan results, asserted BYTE-FOR-BYTE as a test.
Not spot-checked. Not "top-5 matches". Not tolerance-based. Byte identity, over every
golden and every bench query.

  WRITE THE DIFFERENTIAL HARNESS BEFORE THE ACCELERATOR. Written afterwards, it
  will be written to pass. An accelerator that is 99% equivalent produces a fast
  system whose every downstream measurement is quietly untrustworthy, and nothing
  ever errors. This invariant is what the whole tiering story rests on, and M4's
  ARC cache will carry the same discipline.

PLAN before you build. Show me the plan and wait: the on-disk layout of the derived
tier, the block/offset scheme, how `mx` skipping is proven correct, and how the
differential harness gets its query set. I want to see the design before the code.

DEFINITION OF DONE:
  [ ] R3: warm `ask` <= 150ms on the RFC corpus (8,872 docs, manifest-pinned, in the
      lab), INCLUDING WORST-CASE COMMON TERMS. An average over easy queries is not
      R3, and reporting one as R3 breaks the pre-registration law.
  [ ] Differential suite green, byte-for-byte, over goldens + bench
  [ ] Accelerator rebuilds deterministically from committed bytes only
  [ ] `find` / `answer` per the CLI contract; `fux doctor` knows the derived dir
  [ ] fux-playground known_failure class 3 (q008,q017,q030,q031,q036) re-run and the
      XPASS COUNT REPORTED — targets, not DoD; zero closed with R3 met still passes
  [ ] ADR-ACCELERATOR written, with a real reference, accepted
  [ ] OPEN-WORK row + work/open/W-22-*.md DELETED; WORKLOG; DOC-REGISTRY; CHANGELOG

HAZARDS:
  - If the accelerator is slow, the answer is SKIPPING AND BLOCKING, never dropping
    postings. Pruning is forbidden.
  - If R3 fails, that is an honest failure ADR — NOT a licence to start T2/mmap

  - The accelerator is derived and may hold build-varying ints. THE RESULTS MAY NOT

  - Do not touch the committed format (ADR-INDEX-FORMAT, frozen).
  - No floats, no wall-clock, in any committed byte.
```
