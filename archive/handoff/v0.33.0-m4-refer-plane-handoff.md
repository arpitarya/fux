# Handoff — v0.33.0: M4, the refer plane

**Model: Opus for the API shape and the ARC differential; Sonnet for the
adapters and the bench.**

*Why Opus where it is named:* M4 is where **content enters the process for the
first time** in this architecture, and the two proposals graduating into it
(§4) fix the answer contract's shape. An API surface is the expensive thing to
retrofit, and the ARC cache carries the same differential law M2's accelerator
does — an almost-equivalent cache produces a fast system whose every
downstream measurement is quietly wrong. Both are judgment calls no test
catches after the fact.

*Why Sonnet is enough for the rest:* conditional GET, a Confluence REST
client, and a mock-server bench are well-specified implementation against a
written definition of done.

## §1 · Where the build stands

**M0, M1 and M2 have shipped.** `fux ingest` / `build` / `ask` / `find` /
`answer` work end to end. R1 **PASS**, R2 **3/3 PASS**, R3 **PASS** (warm
worst-case p95 27.2 ms on 8 870 RFCs, against a 150 ms bar).

The thing M4 changes: **today every answer is index-only.** `answer` returns
the winning document's title, its heading-derived phrases, and a citation, and
says plainly that passage-level answers arrive with the refer plane. M4 is
that upgrade — the verb exists so this is an upgrade, not a new command.

## §2 · The laws that bind this phase

Same as M2's, plus one new one that only bites here.

1. **`$0` · stdlib-only · deterministic · offline by default.** No new runtime
   dependency, for any reason.
2. **Content is never durable outside its source system.** This is the law the
   whole architecture rests on, and **M4 is the first milestone that can break
   it.** The ARC cache holds fetched bytes *in a derived, gitignored plane with
   a bounded lifetime*. It is a cache, not a copy. The single exception remains
   explicit per-source `snapshot` policy.
3. **Network only inside explicit, fenced, opt-in paths**, enforced by the
   existing import-fence test. `fux ask` must remain answerable offline.
4. **The ARC cache is results-neutral by construction** — a cached answer and
   an uncached answer are byte-identical. Differential law, same discipline as
   the accelerator, and **the harness is written before the cache.**
5. **The adapter cap is HTTP + Confluence.** More systems arrive via
   [`../../work/proposals/mcp-adapters.md`](../../work/proposals/mcp-adapters.md), not code.
6. **A pre-registered threshold may never move** (R4).
7. **Docs move with the work**, and a closed item's row *and* detail file are
   deleted together.
8. **Hashed meta is enforced at write time for every non-git source.** M5 owns
   the enforcement, but M4 is where non-git sources become routine — do not
   leak display text.

## §3 · What lands

### 3.1 Adapters (Sonnet)

- **HTTP** with conditional GET (`ETag`, `If-Modified-Since`), redirect and
  timeout bounds, and honest failure. `304` is a first-class result, not an
  error.
- **Confluence** REST, token from the environment, never from config.
- Both behind one internal fetch interface so the assembler never knows which
  system answered.

### 3.2 The ARC cache (Opus reviews)

Keyed `(loc, sha)` — **content-addressed, so a stale entry is unreachable
rather than wrong**. Derived plane at `.fux/cache/`, `CACHEDIR.TAG`-tagged
(ADR-FUX-DIR reserved it). Bounded by size and entry count, both configurable.

**Write the ARC differential harness before the cache**, exactly as M2 did.
And apply M2's hard-won lesson: **a differential that cannot fail is not a
test.** M2's harness was green while the block bound was replaced by a
constant zero, because the default `top` never exercised it. Before trusting
this one, disable the cache's eviction, or return a deliberately wrong cached
body, and confirm the harness goes red.

### 3.3 Transient convert, chunk, and passage re-score

Fetched bytes are converted, chunked (heading-aware chunker, ported with its
tests), and **re-scored as passages**. The answer cites a fresh `sha`. Nothing
is written back to the committed index.

### 3.4 The freshness fence

Every answer is stamped per citation: `from-index@sha` vs `fetched@sha`. Live
verification sits behind `[freshness] verify`, default off.

### 3.5 `answer` grows up

`fux answer` stops being index-only and returns real passages with citations.
This is the upgrade the M2 verb was shaped for.

## §4 · The two proposals that graduate here — read them first

Both are the same insight on different axes — *how fresh* and *how much* — and
both shape the refer API's **first** surface. Retrofitting either onto shipped
call sites is the expensive version.

### 4.1 [`../../work/proposals/caller-set-freshness-policy.md`](../../work/proposals/caller-set-freshness-policy.md)

`fetch_policy: {max_age_seconds, timeout_seconds}` supplied **by the caller**,
not owned by the engine. Three callers want three different answers from one
index: an agent mid-loop (generous age, tight timeout), a human asking "is this
still true" (age ~0), and **CI or a deterministic replay (`never` — the index
at that commit *is* the answer)**. That third row is why this matters: an
explicit never-fetch bound is what makes a replayed answer reproducible.

Non-negotiables it carries:

- **Age is measured against the ledger's recorded provenance, never wall clock
  at query time.** The no-wall-clock law still binds.
- **The policy is recorded in the answer bundle**, or a replay silently uses a
  different one.
- Offline mode reports honestly that it *could not* meet the requested
  freshness. It never serves stale bytes as fresh.
- **Two integers is the whole surface.** A third knob means the policy belongs
  in config, not in the query.

One question to decide deliberately and record: **does a fetch that times out
fail the query or degrade it?** Almost certainly degrade for agents, almost
certainly fail for `--audit`. That is "policy, per caller" one level down — do
not answer it by accident.

### 4.2 [`../../work/proposals/token-budget-retrieval.md`](../../work/proposals/token-budget-retrieval.md)

`--budget <bytes>` becomes the primary limit; `-k` survives as a secondary cap
and the human default. The engine returns the highest-value assembled answer
that *fits*.

**Fux is unusually well placed to do this honestly**: because passages are
re-scored on fetched bytes, the assembler knows every candidate's real size
rather than estimating from index statistics.

Non-negotiables it carries:

- **Bytes, not tokens, in the engine.** A per-model tokenizer is a
  model-specific dependency and the `$0`/stdlib law forbids it. Callers convert
  at the boundary.
- **Deterministic tie-breaking is mandatory** — equal score-per-byte resolves
  by `(score, sha, locator)`, never set iteration order.
- A per-citation floor so no citation is truncated into incoherence, and a cap
  so one document cannot eat the budget. **The floor needs a real test, not an
  assertion.**
- Greedy score-per-byte is a knapsack *heuristic*. Say so in the ADR; do not
  oversell it.

Decide and record: **does the budget bound the citations or the whole rendered
answer?** Bounding everything is the honest reading of "fits in my context" and
the harder implementation.

### 4.3 The benchmark caution — read before importing any framing

[`../../work/proposals/agent-search-landscape.md`](../../work/proposals/agent-search-landscape.md)
§"Benchmark caution" documents a market where every published comparison is
vendor-run and they contradict each other: Perplexity scores Exa at .781 on
SimpleQA, Linkup scores it at 90.04 % on the same benchmark; Parallel
benchmarked Brave *without giving it a fetch tool* and acknowledges this
"accounts for some of the gap"; Exa's evals have no fixed corpus and are
LLM-graded.

**The reading:** believe only a harness you control, registered before the
number exists. In particular, **do not import Parallel's benchmark framing
along with the token-budget idea** — their comparisons measure search cost plus
LLM token cost combined, which is the metric a token-efficiency-optimized
ranker wins by construction. *The idea can be right and its evidence
self-serving at the same time.*

## §5 · Definition of done

- [ ] **R4 measured**: mock-server bench, cold k=10 ≤ **3 s**, warm ≤ **300 ms**.
      Pre-registered; it may not move.
- [ ] **R4 extended with a freshness sweep** — the same bench at three
      `max_age` settings must show the policy actually moving the
      index-vs-fetch mix. **If it does not, the knob is decoration and gets
      dropped**, and that is a successful outcome, not a failed task.
- [ ] **R4 extended with a budget sweep** — report **answer quality per byte
      returned**, not just latency. If quality-per-byte is flat across budgets,
      the greedy assembler is not earning its complexity and plain top-k with
      truncation wins. Also a successful outcome.
- [ ] **ARC differential green** — cached and uncached answers byte-identical,
      with the harness proven able to fail first.
- [ ] Offline degradation is honest: git sources full function; external
      sources report declared staleness and never fabricate freshness.
- [ ] The import fence still passes — no network import reachable from
      `query/` or `store/`.
- [ ] `fux doctor` understands `.fux/cache/`.
- [ ] **ADR-0007** written, referenced, accepted.
- [ ] Both proposals moved to `archive/` stamped `status: implemented`
      with the ADR link, **in the same change**.
- [ ] `OPEN-WORK.md` row + `open/W-24-*.md` **deleted**; WORKLOG; DOC-REGISTRY;
      CHANGELOG; the conformance run filed under `work/regression/` with its
      evidence **dot-prefixed** (see W-45).

## §6 · Hazards specific to this phase

- **This is the milestone that can break the content law.** A cache with an
  unbounded lifetime, or a "helpful" write-back of fetched text into the
  committed index, ends the architecture's central promise. If you find
  yourself persisting content outside `.fux/cache/`, stop.
- **A results-neutral cache is easy to claim and easy to get subtly wrong.**
  M2's lesson applies verbatim: prove the harness can fail before believing it
  passes.
- **Network in tests.** Everything is a mock server. A test that reaches the
  real internet is non-deterministic and will be deleted.
- **Timeouts are not errors.** A slow source degrades into an honest
  stale-with-disclosure answer under the caller's policy.
- **Do not widen the adapter cap.** Two adapters. MCP is a proposal.
- **Do not build M3's graph lane here**, and do not touch the committed format
  (ADR-INDEX-FORMAT, frozen).
