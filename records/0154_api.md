# SR-API — the importable read surface

## §1 — For humans

```python
from fux import open as fux_open

ix = fux_open(".")
ix.find("rollback", top=5)
ix.ask("how do we roll back a release")
ix.answer("what is the RTO")
```

Until 2026-09-12 the only supported way to use fux from another program was to
spawn it and parse `--json`. `.fux/README.md` said so in as many words: *"the
CLI is the contract; the modules are not."*

**That was fine while there was one reader.** Arpit's ruling — *"Python files
can consume or import these functionalities as well as the node packages can"*
— makes it two, and the same shape has to exist in both.

## §2 — For agents

### Context

`cmd_ask(args)` takes an argparse `Namespace`, prints to stdout, and returns an
exit code. Calling it from Python means faking a Namespace and capturing
stdout. Anyone who wanted fux in-process either did that or re-implemented the
scan.

### Decision

**1. `fux.api` is a supported surface, frozen like any other.**
`open()`, and on the returned `Index`: `find`, `ask`, `answer`, `explain`,
`graph`, `path`. Every return type has `as_dict()`, and that dict is **exactly
the `--json` payload** — same keys, same shapes, same conditional fields.

**2. One schema, three readers.**
[`query/output.schema.json`](../src/fux/query/output.schema.json) already
validated the CLI's JSON. It now validates the Python objects and the Node
objects too. **A consumer that had to re-implement the band rules would be a
second copy of that policy in someone else's language, drifting from the day it
was written** — which is the argument SR-CONFIDENCE already makes for writing
`band` out rather than leaving it derivable.

**3. Nothing that writes is in it.**
No `ingest`, `build`, `add`, `remove`, `update`, `enrich`, `setup`, `hooks`,
`daemon`. The same cut the Node reader makes, so the two surfaces are one
promise and not two.

**4. `open()` enforces the PII gate.**
[SR-PII](0148_pii.md) decision 17 refuses every non-exempt verb without
`.fux/pii.toml`. A library caller that bypassed it would be reading a promise
the CLI does not make — the gate exists so that a redacted index is **the only
index anything reads**, and "anything" includes an import.

**5. The band defaults ON in the library and OFF on the CLI.**
Not an inconsistency: a caller who has gone to the trouble of importing fux has
already decided to read the object, and the block is the part that says whether
to trust it. On the CLI, `--band` is opt-in because `find` pipes bare paths.

**6. 🔴 Every method goes through `run_query` — the SAME seam the CLI uses.**
Fixed 2026-09-12, W-107.

`find` and `ask` called `query.scan.ask` directly, which skips
`.fux/tune.toml`, the archived weighting and the reranker. So
`from fux import open` returned **a different ranking from `fux find`** on the
same index at the same version, silently. Measured on fux's own repo, whose
tune sets `rerank_weight = 0.3`:

| query | `fux.api` | `fux find` |
|---|---|---|
| `graph plane` | 6.392573 | **8.310345** |
| `getUserName` | 13.792954 | **17.930840** |

**It is the same defect as [SR-NODE-SEARCH](0153_node-search.md) decision 8**,
in the third of the three surfaces decision 2 names — and it was found the same
way, by aiming an instrument at the seam the CLI actually uses rather than at
the one the module happened to import. Decision 2 says *one schema, three
readers*; a shared schema does not make a shared **ranking**, and nothing had
ever compared the numbers.

The band comes from `run_query`'s own out-parameter now, so the two
`[confidence]` floors reach it. It was being assembled from the engine's
defaults while the ranking printed beside it used the repository's — one answer
described by two configurations.

**Held by the differential arm since the same day.**
`tools/differential/node_arm.py` runs all six methods on both library surfaces
and compares them, so this cannot silently return.

⚠ **One difference is STATED rather than fixed, because it is a ruling.**
`find(under=…)` here is a prefix **plus a component boundary** — `under="docs/a"`
does not match `docs/ab.md` — while `fux find --under` is a bare prefix, which
`query/__init__.py::_filtered` argues for explicitly (inventing a boundary
would disagree with `Weighting.priority_for`). `fux.api` is frozen by decision
1, so changing it is Arpit's call and not a cleanup. **Named here so it is a
known difference rather than an undiscovered one.**

⚠ **`explain`, `graph` and `path` on this surface are NOT the CLI's payloads
either**, and that predates this record: `{id, community, members, edges}`
against the CLI's `{doc, edges, community}`, a breadth-first best route against
every enumerated route. `node/src/index.mjs` mirrors **this** surface, because
this is its twin — so the two APIs agree and both differ from the two CLIs, in
the same way. Stated; not smoothed over.

**7. `mtime` joins the hit — ADDITIVE, and it is the first amendment this
frozen surface has taken** (2026-09-13, W-153).

Every record in the index carries an `mtime` — the git commit timestamp,
deterministic, written by ingest — and it appeared **nowhere** in
[`query/output.schema.json`](../src/fux/query/output.schema.json). A caller
could not sort by recency, filter by age, or see how old an answer was.

- **Why now.** Closing `recency_half_life_days`
  ([SR-TUNE](0135_tuning.md) decision 15b) removed the only date-awareness fux
  had. `archived_weight` left a fact behind that was already public
  (`archived: bool`); recency left **nothing**. The gap is named here rather
  than discovered by whoever first asks *"how old is this answer?"*.
- **The encoding is the index's own** — an integer of whole UNIX seconds. **A
  second date format in the output would be a second thing to keep true**, and
  a consumer that has to parse two spellings of the same fact has been given a
  bug rather than a field.
- 🔴 **`required: always`, and `null` is a CLAIM.** `mtime` is NOT on every
  record: a corpus copied out of its repository — or one never in git — has none
  anywhere, which `fux doctor`'s `recency prior` row exists to report. So the
  key is always present and `null` says *this document carries no committed
  date*. **An absent key would be indistinguishable from an older fux**, which
  is the W-48 trap this schema states as a rule.
- **All three readers, in one change** — `fux.api.Result`, `node/src/index.mjs`,
  and both MCP servers. `tools/differential/node_arm.py` compares the two
  library surfaces on every run, so a reader that forgot it fails there.
- **It EXPOSES a fact and orders nothing.** `mtime` reaches the sort only
  through [SR-RANKING](0111_ranking.md)'s declared tie-break, at an equal score.
  ⚠ **Sorting or filtering by it — `--as-of`, a recency order — is the unopened
  query-side fork and has no compare doc.**
- ⚠ **Is it BREAKING?** No, under this record's own rule: a consumer reads keys
  it knows and this adds one. **It is stated rather than assumed**, because
  additive is not free — a consumer validating strictly against the old schema
  sees a new key, and the `CHANGELOG` entry says so under *Added* rather than
  letting a patch bump carry it silently.

### Consequences

- 🔴 **This is a frozen surface.** Once documented it cannot churn. Every
  addition is an SR amendment, and every removal is a breaking change. ⚠ **One
  addition has been taken** — `mtime` on the hit, decision 7 — and it is the
  worked example of what that sentence costs: three readers, a schema entry, an
  amendment, and an explicit statement about whether it breaks anybody.
- ⚠ **`cmd_ask` and friends do not call into it yet.** The finished shape is
  `cmd_ask(args) -> print(render(api.ask(...)))`, so there is exactly one
  implementation. Today `api.py` assembles `find` and `ask` from the same
  primitives while `answer` is routed through `cmd_answer` — **a deliberate
  staging, recorded here so it cannot pass for the design.** Until the renderer
  split lands, a change to how `ask` assembles its payload has two places to
  change.
- **The Python modules stay unsupported.** `fux.query.scan` is not a contract
  and does not become one by being importable; `fux.api` is the line.

### Alternatives

- **Leave the CLI as the only contract** — which is what the repo said until
  the second reader existed. A Node package that could be imported and a Python
  package that could not would be an odd product.
- **Expose the existing modules and call that the API** — cheaper, and it
  freezes every internal name in place. The seam is worth a file.
- **Do the renderer refactor first** — the correct order, and it touches a
  1 481-line hot file. Landed with a green `pytest`, not blind.
