# W-227 — the 2026-09-27 L11 breach

**Model: NONE.** This is a ruling, not a build.

🔴 **Declared under [L11](../../records/0012_LAW-11-sealed-answer-key.md)** by
the session that caused it: Claude Code, Opus, 2026-09-27, ~22:20 IST. The
[WORKLOG](../WORKLOG.md) entry of the same date gives the full account. This
file gives the declaration an id, so the inbox row has one (queue rule 6).

## What happened

- I was closing W-226 and wanted to check that no live doc still linked to its
  detail file. I ran:
  `grep -rn "open/W-226" work records docs src CLAUDE.md 2>/dev/null | grep -v "^work/golden"`.
  `work` was a root with no `--exclude-dir=golden`, so the traversal read every
  file under `work/golden/`, key directory included, if one exists. Only the
  **output** was filtered.
- **Nothing was printed.** The string `open/W-226` cannot occur in a key, so no
  answer text and no file name from the key directory reached the context.
- This is the **same route as [W-223](../../archive/open/W-223-l11-breach-2026-09-25.md)**,
  in the same shape: output filter, no traversal exclusion. It is the second
  occurrence.

## ⚠ The guard did not fire

`.claude/hooks/guard-golden-traversal.sh` (W-223's hard guard) is registered in
`.claude/settings.json`. Replayed alone through the hook, the grep line is
**denied** (exit 2), with or without its `| grep -v` tail. In the session it ran
as the **last line of a multi-line Bash command** that began
`cd … && git mv … && python3 - <<'EOF'`, with a heredoc Python body, followed by
a second `grep -n` line. Whole, that command was **allowed**.

I have not isolated which part of the command defeats the parser. When I tried
to replay the whole command through the hook, the auto-mode classifier refused
it as probing a security guard for a bypass. I stopped there, so the diagnosis
is Arpit's to authorise.

## What it touches

- **No measurement was running.** This session has captured nothing and scored
  nothing. Every golden number is already `informed` (L11 decision 14).
- W-168's phase-5 run of `set-4-claude` is **not run by this session** until
  Arpit rules. Another session may run it.

## 🔴 What Arpit decides

1. Whether this breach costs anything beyond what is already `informed`.
2. Whether a session may diagnose and harden the traversal guard for
   multi-line and heredoc commands. That needs replaying commands through the
   hook, which the classifier blocks without his say-so. The alternative is to
   record the gap as accepted in L11 decision 9.
