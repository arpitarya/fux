# W-202 — freeze what the analyzer does to an identifier

**Model: Sonnet.** One test file, one frozen fixture, no production code and no
decision in it.

**Graduated 2026-09-20 from
[`proposals/identifier-exact-match.md`](../proposals/identifier-exact-match.md) §5
(gate A).** Arpit, 2026-09-18: *"we will run test cases before that gets
implemented and after that gets implemented."* This is the **before**, and it is
the half that waits on nothing.

## Why it earns a row of its own

**Every other identifier thread is blocked and this one is not.** W-168 step 2
needs a seed corpus of the failing shape; [W-201 → W-205](W-205-identifiers-reachable-and-whole.md)
needs Arpit's ruling on which frontmatter keys are indexed;
[W-203 → W-205](W-205-identifiers-reachable-and-whole.md) waits on W-168. **None of them can
be measured against a before-state that is not written down**, and the
before-state currently lives in two regression reports that disagree with each
other.

⚠ **It also locks in the correction.** The
[survival report](../regression/2026-09-16-identifier-survival/report.md) said a
mangled identifier *"cannot be reached at all"*; the
[headroom run](../regression/2026-09-18-identifier-headroom/report.md) measured
**~90 % top-3 at every rung** and showed mangling is **symmetric** — ingest and
query import the same `analyze()`. A frozen fixture makes that fact executable
rather than a paragraph two reports argue about.

## Definition of done

1. **A frozen fixture** of the 33 distinct seed identifiers, each with the
   tokens [`query/analyzer.py`](../../src/fux/query/analyzer.py) produces
   **today**, plus three derived flags: `survives_whole`, `mangled` (a produced
   token is not among the separator-split parts of the original — **not** the
   substring test, which reported 1 instead of 3), and `separator`.
2. **A test that asserts the fixture exactly**, and fails loudly with the
   identifier, the expected tokens and the produced tokens when any of them move.
3. **Both separators are covered.** ⚠ A fixture of underscore ids alone passes
   while proving nothing — `ERR_2031` already survives whole and `RF-118` does
   not, and the underscore case half-working is the trap the analysis names.
4. **Stdlib only, offline, no index required.** `analyze()` imports only
   `query/stem.py`; the test must not need a built corpus, so it runs in any
   environment including a Cowork bridge shell.
5. **The test states in its docstring that it is a mechanism probe, never a
   ranking verdict** — the W-191 lesson, written where the next reader is.

## Out of scope

- **Changing the analyzer.** Not one byte of `src/`. That is W-203.
- **Any claim about ranking quality.** No arm, no bar, no pre-registration —
  [SR-RS](../../records/0133_predictions.md) decision 19 does not apply because
  nothing is being compared.
- **Frontmatter.** W-201 owns the meta/body split.

## Key files

- [`src/fux/query/analyzer.py`](../../src/fux/query/analyzer.py) — read only.
- [`src/fux/query/stem.py`](../../src/fux/query/stem.py) — `should_stem` is the
  reason three ids are mangled; read only.
- `tools/quality-controls/identifier_survival.py` — the existing instrument, and
  the source of the 33 rows.
- `work/regression/2026-09-16-identifier-survival/evidence/per-identifier-rows.jsonl`
  — the 33 rows as first measured. ⚠ Re-derive the flags rather than trusting
  the file's own `mangled` column; that column is what the detector bug produced.

## Hazards

- ⚠ **A fixture generated by the code it tests proves nothing.** The expected
  tokens are committed literals, reviewed once by a human against the report's
  tables — not a golden file regenerated by running `analyze()`.
- ⚠ **`getUserName` → `getusernam` is CORRECT and must stay in the fixture.**
  The whole token is stemmed too; it matches because the query is stemmed
  identically. A reader who "fixes" it has broken the symmetry the headroom run
  measured.
