# PRE-REGISTRATION — W-233, identifier families

🔴 **FROZEN, and committed before any number exists**
([SR-RS](../../../records/0133_predictions.md) decision 10b). **No arm has run,
and the mechanism is not built yet.** The query sets under `evidence/` were
generated by the rule in §3 **before** any engine carrying the mechanism
existed, and they are frozen with this file.

## 1 · The defect, and the mechanism

**The defect** ([fixture run](../2026-09-28-identifier-fixture/report.md)): v3
keeps `RF-118` whole only when it is written `RF-118`.

- `RF 118`, `RF–118` and `ADR-4` (for `ADR-0004`) reach the parts only, and the
  exact document ranks **2nd** below a shared-parts neighbour.
- `rf118` reaches nothing at all.

**The mechanism** ([compare doc](../../compare/identifiers-whole.compare.md),
S1–S8):

- families in `.fux/identifiers.toml` are matched against the text on both
  sides;
- each match adds one canonical term beside v3's unchanged output;
- the effective rules' digest is stamped into each shard header.

## 2 · The arms

| arm | engine | the arm's `.fux/identifiers.toml` |
|---|---|---|
| **before** | the commit that freezes this file | does not exist (the feature does not) |
| **after** | the W-233 build | what `fux identifiers --write` writes on that arm's copy, with the shipped `inspect.toml` defaults (`min_values = 3`, `min_docs = 2`), **never hand-edited** |

- Each arm gets its own copy from
  [`arm_corpus.py`](../../../tools/quality-controls/arm_corpus.py).
- The after arm then runs `fux identifiers --write` and `fux ingest`.
- The written file is filed per rung as evidence.

⚠ **Why an engine build and not a tunable at zero.** The feature is inert by
construction until the file holds a family. **G3 below proves that inertness
byte for byte.** So the variable under test is *the families written on this
corpus*, which is exactly what a user who runs the verb gets.

## 3 · The query sets: frozen, by rule

The sets were generated by
[`identifier_variants.py`](../../../tools/quality-controls/identifier_variants.py)
at `--per-family 3`, whose docstring states the rule:

- letter-prefixed shape families of ≥ 3 values in ≥ 2 documents;
- only ids found in **exactly one** non-archived document, so the primary is
  unambiguous;
- the variants `exact`, `space`, `nosep`, `endash` and `unpadded`.

| rung | ids | families | queries | exact | space | nosep | endash | unpadded |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| rung-00100 | 28 | 11 | 115 | 28 | 28 | 21 | 28 | 10 |
| rung-01000 | 119 | 41 | 451 | 119 | 119 | 84 | 119 | 10 |
| rung-10000 | 113 | 41 | 433 | 113 | 113 | 84 | 113 | 10 |

The files are `evidence/variants-<rung>.jsonl`. 🔴 **No row is added, removed or
retargeted after this file is committed.** A row found broken is reported, and
it is counted in both arms alike.

## 4 · Three gates, checked before any ranking arm is read

- **G1 · parity.** For every query in the three sets, Node's analysis under the
  after arm's rules equals Python's, term for term. **One divergence stops the
  run.**
- **G2 · determinism.** The after arm's `.fux/index/` is byte-identical over
  two from-scratch ingests of each rung (L4).
- **G3 · inertness.** On `rung-01000`, the W-233 engine with an
  **empty** `identifiers.toml` writes a `.fux/index/` byte-identical to the
  before arm's. This is the property that makes "no file, no change" true, and
  that makes an empty file a rollback.

## 5 · Endpoints, the floor, both directions

All endpoints are `hit@1` of the primary, **paired per query between the
arms**, per rung. The floor is
[SR-RS](../../../records/0133_predictions.md) decision 19's **net of 6**, and it
tracks the flips, never the population.

- **E1 · the fix:** the non-`exact` rows (`space`, `nosep`, `endash` and
  `unpadded` pooled; each is also reported alone, never judged alone).
- **E2 · the guard:** the `exact` rows. The mechanism must not cost the case
  that already works.
- **E3 · the prose control:** 60 questions from the **retired** set 1
  (`work/golden/retired/set-1/questions.jsonl`, text only). Every other id in
  file order, capped at 60, exactly W-205's rule. Run on `rung-01000`, it
  counts **the questions whose rank-1 document changes** between arms. It needs
  no key.

**The verdict:**

- **PASS** — all of:
  - E1 has a net of **≥ +6** on at least one rung;
  - no rung has a net of **≤ −6** on E1 or E2;
  - E3 changes **fewer than 6** of 60;
  - G1–G3 hold.

  The mechanism ships: the verb, the file, both readers, the doctor rows, and
  the Identifiers tab.
- **FAIL** — any of:
  - a net of ≤ −6 on E1 or E2 on any rung;
  - E3 ≥ 6;
  - a gate broken.

  The mechanism does not ship, and the record names the failing clause.
- **INCONCLUSIVE** — anything else. **It does not ship on an inconclusive**,
  which is W-205's rule, kept.

## 6 · Headroom, disclosed from the before arm (decision 22)

The before arm's E1 and E2 misses per rung are reported **before** any net is
quoted. They are the only room each direction has. If E1's before-arm misses
are below 6 on every rung, the run cannot return a verdict and is filed
`unmeasurable` (decision 23b).

## 7 · Cost: reported, no threshold

For each rung and both arms, the run reports:

- committed `.fux/index/` bytes;
- distinct terms and postings;
- ingest wall-clock;
- the number of detected families.

🔴 **No cost bar is set**, for W-205's reason: a bar invented here is one nobody
ratified. A large number goes to the verdict and to Arpit.

## 8 · What this run may never do

- Claim B4 (an ID inside a path or URL), a document written with a Unicode
  dash, a `#nnn` reference or a hex prefix is fixed **on the ladder**. The
  ladder carries none of them ([fixture](../2026-09-28-identifier-fixture/ANALYSIS.md)
  §7), so those are fixture-tested only.
- Hand-edit the after arm's `identifiers.toml`, or change `min_values` and
  `min_docs` after an arm has run.
- Pool rungs, or judge a single variant.

## 9 · Classification

**`informed`.** The query sets were generated by a rule this session wrote,
over a ladder this model family co-authored, and the tree has been unlocked
since 2026-09-21 (L11). **No golden answer is used, needed or reachable.** An
id-query carries no answer, and E3 reads retired question text only.
