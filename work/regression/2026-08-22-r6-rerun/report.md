**Tier 3's two assertions both held**: git reported the conflict *and* the shard
file carried ordinary `<<<<<<< ours` / `>>>>>>> theirs` markers with both sides'
bytes intact. The driver refused rather than picking, which is the asymmetry the
whole design rests on.

**Tier 2's edit-survival assertion held**: both sides' `ver` advanced past 1, so
the clean merge was last-writer-wins *per line*, not a file-level pick that
silently dropped one side.

## What changed since 2026-08-20

Only the instrument, and only in two places:

1. **Tier 1 selects its two added documents by hashing** so they land in one
   shard file. Previously it added two documents wherever they fell, which is
   usually two different shards — a case git's textual merge handles unaided,
   so the tier could pass while proving nothing.
2. **The verdict table gained a `PARTIAL` row** for *all tiers match, exactly
   one of tiers 1/2 informative* — the case the 2026-08-20 table did not cover
   and into which that run's result fell. It routes to Arpit rather than
   resolving.

**The threshold is unchanged and uncopied-loosely**: *machine planes
conflict-free, human conflicts preserved.*
